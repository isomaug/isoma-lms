# Week 7 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Write a complete 7-section design brief: Problem Statement, Target User, Solution Description, How It Works (step-by-step), English/Math Connection, Test Results, Improvements Made
- Build a working Arduino prototype that responds to at least one input and produces at least one output
- Test the prototype systematically and record test results in the design brief (minimum 3 test runs)
- Iterate on the design based on test results — make at least one documented improvement
- Give and receive structured peer review feedback using the 5-question rubric
- Prepare a 5-minute Demo Day presentation: Problem -> Solution -> Live Demo -> Evidence -> Reflection

## Continue

### 3. INDEPENDENT / PAIR WORK Iterate, Test & Peer Review
1. Task 1 (25 min): Iteration cycle — test -> identify what does not work -> fix -> test again. Complete at least 3 rows in the Test Record Table. Each row must have a specific "Action Taken" — not just "Fixed it."
2. Task 2 (15 min): Peer Review — swap projects with an adjacent pair. The reviewing pair completes the 5-question Peer Review Rubric: (1) Does the project respond to input? (2) Does it produce a clear output? (3) Is the design brief complete? (4) Is the Math connection clearly demonstrated? (5) One suggestion for improvement.
3. Task 3 (10 min): Act on peer feedback — make at least one documented change based on the feedback. Record in "Improvements Made" section of the design brief.
4. You priority during this phase: check that EVERY design brief has an English/Math Connection section completed. This is a mandatory ILO 3.4 requirement.
5. Extension: Add Serial.println() output that displays a measurement, calculation, or data point during every loop iteration — quantifying the project's behaviour.
### 4. SHOWCASE & DEBRIEF
6. Each pair does a 2-minute preview demo — project must run during this time. One partner presents, one supports the hardware.
7. Class gives one piece of feedback for you: "I noticed… / I wonder if…" Record on board.
8. Presentation preparation: you explains Demo Day structure — Problem -> Solution -> Live Demo -> Evidence (show the math) -> Reflection. Write the 5 sections on the board. You spend last 5 minutes planning what they will say for each section.
9. English close: "Your design brief IS your evidence. A well-written brief shows you thought before you built."
10. Math close: "When you present your math connection, show the number. Don't just say 'it uses a loop' — say 'the loop runs 7 times and produces the 7 times table'. Numbers are evidence."
11. Collect completed Design Briefs (all 7 sections including Test Results and Improvements Made) as this week's artifact.
