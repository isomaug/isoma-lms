- Deliver a 5-minute formal presentation to a panel (you + invited assessor) following the structure: Problem -> Solution -> Live Demo -> Evidence -> Reflection

- Explain at least one coding concept used (loop, condition, variable, function) in plain English to a non-technical audience
- Present at least one quantified mathematical outcome — a measurement, calculation, or data point from the project — displayed on a graph or in a data table
- Read a written introduction and conclusion from prepared notes
- Answer a minimum of 2 questions from the panel about the project design, coding decisions, or mathematical elements

## Check your understanding
- Evidence Required
- Demo Day Project (30%)
- Prototype functionality (10%): runs correctly, responds to input, correct output. Code quality (10%): variables, loops, functions, comments. Integration (10%): explicit English AND Math connection demonstrated.
- Panel scores on Demo Day Assessment Rubric — DDD Part 8.6. Both assessors score independently.
- Presentation (20%)
- 5-minute formal presentation: problem framing (5%), solution + live demo (5%), evidence + data (5%), reflection + next steps (5%). Panel of 2: you + invited assessor.
- Rubric scores from both panel members. Moderated if >10% difference.
- Written Design Brief (10%)
- All 7 sections complete (4%): completeness. Clarity of written English (3%). Accuracy of mathematical element (3%). Submitted before presenting — not accepted after.
- Design Brief document filed. Scored by you on 10-point sub-rubric.
- Peer Review (5%)
- Quality and constructiveness of written peer feedback provided to a classmate. Scored on specificity, evidence-based comments, and constructive tone. Not graded on what score was given.
- Peer Feedback Rubric forms collected for all 8 you.
