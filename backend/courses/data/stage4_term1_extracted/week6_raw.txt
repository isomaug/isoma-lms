Identify what LED animation represents each scene and which button press triggers the next scene
Code each scene as an if/else block in MakeCode, triggered by Button A (next scene) and Button B (restart story)
Test the full 3-scene story, confirm all transitions work, and revise any errors
Calculate the total animation duration (sum of scene durations) and express Scene 1 as a fraction of the total
Present the story to the group using the written plan, explaining what each scene shows on the LED

Story plan template (A4 per learner) – three boxes: Scene 1 / Scene 2 / Scene 3, each with: Story text, LED animation description, Duration (seconds), Button trigger
LED icon reference card per pair – showing all available MakeCode icons (heart, duck, house, snake, arrow, etc.)

Facilitator device + projected screen
Facilitator shows a Micro:bit pre-loaded with a 3-scene animation (heart → snake → house). Run it twice. Ask: 'What story could this be telling? What happens in each scene?'
Bridge: 'Every story has a structure: something happens (Setting), then a problem appears (Conflict), then it gets solved (Resolution). Your animation will use the same structure.'
Show examples of narrative starters: 'One morning a small bird was singing peacefully… Suddenly a storm arrived… Finally the sun returned.' Learners identify: which line is Setting / Conflict / Resolution?
Maths hook: 'If Scene 1 lasts 4 seconds and Scene 2 lasts 6 seconds – what fraction of the first two scenes is Scene 1?' (Answer: 4/10 = 2/5). Confirm together.
Distribute story plan templates and LED icon reference cards. Each learner writes their 3-scene story. Rule: write the story text BEFORE choosing the LED icons. The story drives the code – not the other way around.
For each scene: choose an LED icon that represents it; choose a duration (3–8 seconds); note which button triggers the next scene.
Maths: calculate total story duration (Scene 1 + Scene 2 + Scene 3). Express Scene 1 as a fraction of the total. Write on the plan.
Pairs peer-review each other's plans: 'Does Scene 1 set the scene? Is there a clear problem in Scene 2? Is it resolved in Scene 3?' Give one suggestion for improvement before coding starts.
Step 1 – Scene Variable (5 min): Driver opens MakeCode. Create a variable called 'scene' (set to 0 in 'on start'). This will track which scene is active.
Step 2 – Scene Logic (10 min): Build: 'on button A pressed → change scene by 1 → if scene = 1 → show icon [Scene 1 icon] → pause [duration]ms → if scene = 2 → show icon [Scene 2 icon] → pause [duration]ms → if scene = 3 → show icon [Scene 3 icon] → pause [duration]ms'. Download and test.
Step 3 – Restart Button (5 min): Add 'on button B pressed → set scene to 0 → clear screen'. This lets the story restart from the beginning. Download and test the full story flow.
Step 4 – Revision (5 min): Swap Driver/Navigator. Navigator runs the story and checks: Does each scene appear? Do the transitions work? Does Button B restart? Identify any bugs and fix them.
Gallery: each pair runs their story animation. The learner who wrote the plan reads each scene aloud using their story text while the animation plays.
Audience completes 'One Star, One Wish' peer review cards: Star = what worked well; Wish = one suggestion for improvement.
Facilitator asks 3 learners: 'What is the total duration of your animation? What fraction is Scene 1? What does Button B do?'
Revise: learners read their peer review card and write one improvement in pencil on their story plan. If time allows, implement the improvement in MakeCode.
