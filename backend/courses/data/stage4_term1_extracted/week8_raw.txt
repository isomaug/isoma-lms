Distribute presentation structure cards. Pairs have 10 minutes of silent preparation time: review the design brief, check the programme is working, and practise the 5-section presentation using the sentence starters.
Facilitator circulates: check each project is running correctly. If a critical bug is found, the facilitator may ask a guided question ('What does this block do?') but must not fix the code for the learner.
2-minute rehearsal: each learner quietly practises their opening ('The problem I noticed was…') and their maths statement ('One mathematical element in my project is…').
Technical check: plug in all Micro:bits and confirm programmes are downloaded and running before presentations begin.
Presentation order: each pair presents individually (not together). Partner may hold the Micro:bit during the demo but must not speak. Each presenter: maximum 3 minutes + 1 minute for audience questions.
Structure enforced: facilitator uses a finger count to signal which section the learner should be on (1=Problem, 2=Solution, 3=Demo, 4=Learned, 5=Improve). Gently prompt if a learner skips a section.
Demo moment: when the learner reaches the Demo section, they run the programme live. Audience watches silently. After the demo, the learner explains one maths element using a number, calculation, or data point.
Audience: while one learner presents, all other learners complete the peer feedback rubric for that presenter. Feedback must be written – not just ticks. At least one written sentence per rubric.
Facilitator leads a group reflection: 'What is one coding concept every project used this term? What is one maths concept that appeared in more than one project?'
