## Continue

### SESSION 3 / DAY 3 — Iterate, Complete Tests, Peer Review, Rehearse  (50 min)
1. Test Cycle 3 (10 min): test the AI classification or alert element. Run 10 inputs through yourselfifier (manually set conditions, or use the Serial command interface). Record the true class for each and the predicted class. Calculate: accuracy = correct ÷ 10. Record in the Test Results section of the brief. If accuracy is below 70%, identify the most common misclassification and propose a specific threshold adjustment that would address it.
2. Code review self-assessment (5 min): apply the 6-criterion code review rubric from T3 Week 1 to the learner's own sketch. Score every criterion honestly — facilitated by the reminder that the peer reviewer will also score it and significant discrepancies must be discussed. A self-score of 4 requires at least one line of evidence (e.g. "I scored 4 for Comments because every function has a // PSEUDOCODE LINE N: cross-reference and a plain-English purpose statement").
3. Peer review (15 min): swap the full submission package (design brief, algorithm paper, acceptance criteria log, code review self-assessment) with a partner pair. Apply the 8-question peer review rubric. Q8 is new: "Does the code review self-assessment appear honest? If you disagree with any self-score, cite the specific criterion and the specific evidence." Return with feedback. Read and initial receipt.
4. Presentation rehearsal (10 min): you delivers the 5-minute structure to yourself: Problem -> Algorithm (hold up and briefly explain the flowchart) -> Live Demo -> Statistical Evidence (state one quantitative result from the test cycles) -> Reflection (Term One to Term Three growth in one clear sentence per term). Partner gives 1 Star + 1 Wish. You listens to at least 2 rehearsals.
5. 2 you give a full presentation rehearsal (5 minutes each). Observe and completes Questions 1–4 of the peer review rubric for the presenter as Demo Day preparation practice.

## Stay safe
Safeguarding Note: All capstone project ideas must be reviewed and approved by the you before building begins. Projects that monitor individuals (motion detection, sound recording, facial recognition — even as concept demonstrations) must be declined and redirected. Multi-sensor circuits with both LDR and TMP36 simultaneously require the you to verify orientation of all components before USB connection. The buzzer should be tested briefly — sustained output in a small room can cause distress. All design brief personal information must use first name only. USB flash drive submissions must contain no personal files from outside the programme.
