# Week 4 - Lesson 1

## Session length
**About half of this week's plan** (you will finish in Lesson 2)

## Today you will learn
- Collect a labelled dataset of 30 dual-sensor readings (LDR + TMP36), each manually labelled as one of 3 environment classes: COMFORTABLE, WARM, DIM — recording both raw values and class labels in a data table
- Engineer two derived features from the raw sensor data: (1) a normalised light score = ldrValue ÷ 1023.0 (range 0.0 to 1.0) and (2) a heat index approximation using the TMP36 value, stored as floats
- Write classification rules based on the training dataset — inspecting the data to find the threshold values that most accurately separate the 3 classes — and implement them as a nested if/else Arduino classifier
- Evaluate yourselfifier on a held-out test set of 10 new readings using a confusion matrix: rows = true class, columns = predicted class
- Calculate precision, recall, and accuracy from the confusion matrix: accuracy = correct predictions ÷ total predictions; precision for class C = true positives for C ÷ all predictions of C; recall for class C = true positives for C ÷ all actual instances of C
- Write a 150-word AI Evaluation Report: what yourselfifier does, how it was trained, its accuracy, one source of bias in the training data, and one specific improvement that would increase accuracy

## Big idea
Real machine learning has five stages: collect data, engineer features, train a model, test it, and evaluate its performance. You cannot skip a stage. Today you complete all five — using Arduino as your data collection and classification platform.

- USB flash drives
- A computer screen to follow along

## Links to English and Maths
- **English:** The AI Evaluation Report is a piece of professional technical writing that mirrors the abstract and conclusions section of a research paper. It must synthesise four types of information: a description of the system, a summary of the methodology, a statement of results with numbers, and an evidence-based critique. "This classifier achieved an accuracy of 70% on the 10-item test set. The primary source of error was misclassification of the DIM class — 3 of the 4 DIM readings were classified as COMFORTABLE. This occurred because the training data contained only 6 DIM readings, making the rule boundary imprecise. Adding 10 more DIM readings to the training set, collected under genuinely dark conditions, would likely improve recall for the DIM class from 25% to over 70%." This writing standard — precise, data-grounded, specific about error sources, specific about improvement — is the highest English writing standard in the programme.
- **Maths:** Precision and recall are the core evaluation metrics of any classification system. For a 3-class classifier evaluated on 10 test items: accuracy = total correct ÷ 10. Precision for COMFORTABLE = (number correctly classified as COMFORTABLE) ÷ (total classified as COMFORTABLE — including incorrect ones). Recall for COMFORTABLE = (number correctly classified as COMFORTABLE) ÷ (total that are actually COMFORTABLE in the test set). A confusion matrix makes this visual: the diagonal cells are the correct predictions; the off-diagonal cells are the errors. You read the matrix and identify which class was most often confused with which other class. Feature normalisation: dividing ldrValue by 1023.0 maps the sensor range (0–1023) to a unit interval (0.0–1.0) — this is linear normalisation, a standard pre-processing step in every machine learning pipeline. You calculate: if ldrValue = 750, normalised score = 750 ÷ 1023.0 = 0.733. This is a float division calculation requiring correct understanding of integer vs float arithmetic.

## Let's begin

### WARM-UP & REVIEW — The Five Stages of Machine Learning  (20 min)
1. Draw the AI pipeline on the board: (1) COLLECT DATA -> (2) ENGINEER FEATURES -> (3) WRITE RULES / TRAIN MODEL -> (4) TEST ON HELD-OUT DATA -> (5) EVALUATE PERFORMANCE. "Terms One and Two covered stages 1 and 3 in isolation. Today you do all five in sequence — exactly as a professional machine learning engineer would."
2. Recall Term Two Week 6: "Last term, your decision tree classifier was trained on informal observations — you chose thresholds by intuition. Today you choose thresholds by inspecting actual data. That difference — intuition versus evidence — is the difference between a guess and a model."
3. Introduce precision and recall with a physical example (5 min): "Imagine a spam filter. It reviews 10 emails. 4 are truly spam. The filter marks 5 as spam. But 2 of the 5 it marked as spam are actually legitimate emails. Precision = 3 ÷ 5 = 60% (of everything it called spam, 60% was actually spam). Recall = 3 ÷ 4 = 75% (of all the actual spam, it caught 75%). Which matters more — precision or recall?" Discuss. Answer depends on context: for spam, low precision wastes time; for a medical test, low recall means missed diagnoses.
4. Get ready to use all printed materials. Explain the session structure: "First 60 minutes — collect training data and write rules. Final 50 minutes — test your classifier on cards you have never seen, build the confusion matrix, calculate the metrics, write the report."
5. Data collection sketch (10 min): write a sketch that reads both sensors every 2 seconds and prints: "LDR: [value] | Temp: [°C] | LightScore: [normalised]" to Serial Monitor. The normalised light score uses float lightScore = ldrValue / 1023.0;. Upload and verify both raw values and normalised score appear. Confirm float division is working correctly: if ldrValue = 0, lightScore should be 0.00; if ldrValue = 1023, lightScore should be 1.00.

### GUIDED ACTIVITY — Data Collection, Feature Engineering, Rule Writing  (60 min)
6. Training data collection (25 min): collect 30 labelled readings. For each reading, manually label the true class in the training data table: COMFORTABLE (good light, comfortable temperature), WARM (too hot regardless of light), or DIM (too dark regardless of temperature). Vary conditions deliberately: cover the LDR, hold a warm hand near the TMP36, open a window or door. Aim for at least 8 readings of each class — note if any class is under-represented, as this introduces training data bias.
7. Feature engineering — add heat index (10 min): the raw TMP36 value has been converted to °C. Now engineer a second derived feature: bool isHot = (tempC > 27.0); — a Boolean that captures whether the temperature exceeds the comfort threshold. Extend the data table to include an isHot column and fill it for all 30 readings. Discuss: "This derived feature reduces a continuous float to a binary signal. Why might that make classification easier? What information is lost?"
8. Rule writing from data (15 min): inspect the training data table. For each class, find the range of lightScore and tempC values. The COMFORTABLE class should cluster around high lightScore AND low tempC. WARM clusters around high tempC regardless of lightScore. DIM clusters around low lightScore regardless of tempC. Write the threshold values on the rule writing worksheet with justification: "We chose lightScore < 0.35 for DIM because all 8 DIM readings had lightScore below 0.38, while all COMFORTABLE readings were above 0.40." Implement the rules as a nested if/else classifier in the Arduino sketch.
9. Held-out test set (15 min): you distributes the 10 test set cards face-down. For each card, you read the LDR and TMP36 values, run yourselfifier sketch with those values (type them into a Serial.parseInt() input or hard-code each one temporarily), record the PREDICTED class from Serial Monitor output, then flip the card to reveal the TRUE class. Record both in the confusion matrix template. Do not look at the true class until after the prediction is made.
10. Confusion matrix completion (10 min): fill the 3×3 confusion matrix. Each row represents the true class; each column represents the predicted class. The diagonal cells (true COMFORTABLE predicted COMFORTABLE, etc.) are correct predictions. All off-diagonal cells are errors. Sum the diagonal: total correct predictions. Calculate accuracy = total correct ÷ 10.
