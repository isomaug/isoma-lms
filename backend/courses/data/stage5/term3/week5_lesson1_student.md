# Week 5 - Lesson 1

## Session length
**About half of this week's plan** (you will finish in Lesson 2)

## Today you will learn
- Design and write a DataReading struct with fields: int id, float ldrNorm, float tempC, unsigned long timestamp, String label — and declare an array of 50 such structs as the programme's data store
- Write a complete data logger programme using millis()-based non-blocking timing that: reads both sensors every 5 seconds, stores each reading into the struct array, computes live running statistics (mean, min, max, range) for both ldrNorm and tempC after each new reading, and prints a formatted data log line to Serial Monitor
- Implement Serial command control: "START" begins logging, "STOP" pauses logging, "REPORT" prints the full statistics summary, "RESET" clears the array and resets all statistics — all without blocking the timing loop
- Calculate the percentage deviation of each new reading from the current running mean: deviation = ((newValue − currentMean) ÷ currentMean) × 100.0 — print an alert to Serial Monitor if deviation exceeds 20%
- Write a full Technical System Documentation Report (minimum 150 words) structured as: System Overview | Hardware Components | Software Architecture (function list with one-sentence description each) | Statistical Methods Used | Sample Output (transcribed from Serial Monitor) | Limitations and Improvements
- Evaluate the programme against 4 self-defined acceptance criteria written before coding begins — confirming each criterion as Met, Partially Met, or Not Met with evidence from the live output

## Big idea
Every professional data system does the same four things: collect, store, process, and report. Today you build all four into one programme — a real data logger that a scientist or engineer would recognise.

## Links to English and Maths
- **English:** Technical System Documentation is the highest-register technical writing task you have encountered. Unlike a scientific report (which describes an experiment) or a design brief (which describes an intention), a system documentation describes an existing working system from the perspective of someone who must maintain or extend it. The Software Architecture section must list every function, its purpose in one precise sentence, what it receives, and what it produces — exactly like the architecture map from T3 Week 1, but now for a system the learner designed themselves. The Sample Output section requires you to transcribe a real excerpt from the Serial Monitor and annotate it: explaining what each printed line means and which function produced it. The Limitations section must be analytically honest: "The programme cannot store more than 50 readings — after 50, new data overwrites old data or the logger must stop. This limits continuous monitoring to 50 × 5 = 250 seconds = 4.2 minutes."
- **Maths:** Running statistics require understanding that statistics can be updated incrementally rather than recalculated from scratch each time. Running mean after n readings = ((previous mean × (n−1)) + newValue) ÷ n — Welford's method avoids summing all values for every update. Running min and max are simpler: compare the new value to the current min/max and update if necessary. Percentage deviation: deviation = ((newValue − mean) ÷ mean) × 100.0. A deviation of 20% triggers an alert. You calculate by hand: if the current mean ldrNorm is 0.620 and a new reading is 0.310, deviation = ((0.310 − 0.620) ÷ 0.620) × 100.0 = −50.0% — a significant drop that should trigger an alert. Time-series graph: plot ldrNorm and tempC on the same time axis (x = reading number, y = normalised value 0.0–1.0 for ldrNorm; secondary scale for tempC). This is the most complex graph in the programme — two dependent variables on the same x-axis.

### GUIDED ACTIVITY — Struct Design and Core Logger Build  (60 min)
6. Core sensing and storage function (15 min): write void takeReading() { if(readCount >= 50) return; int raw = analogRead(A0); float ldr = raw / 1023.0; float temp = (analogRead(A1) * 5.0 / 1024.0 - 0.5) * 100.0; readings[readCount] = {readCount, ldr, temp, millis(), ""}; updateStats(ldr, temp); printReadingLine(readCount); readCount++; } You write this in full.
7. Running statistics function (15 min): write void updateStats(float ldr, float temp) { int n = readCount + 1; ldrMean = ((ldrMean * readCount) + ldr) / n; if(ldr < ldrMin) ldrMin = ldr; if(ldr > ldrMax) ldrMax = ldr; tempMean = ((tempMean * readCount) + temp) / n; if(temp < tempMin) tempMin = temp; if(temp > tempMax) tempMax = temp; float ldrDev = ((ldr - ldrMean) / ldrMean) * 100.0; if(abs(ldrDev) > 20.0) { Serial.print("ALERT: LDR deviation "); Serial.print(ldrDev); Serial.println("%"); } } Hand-calculate a worked example first — see maths section — before typing.
8. Serial command handler (10 min): write void handleSerial() { if(Serial.available() > 0) { String cmd = Serial.readString(); cmd.trim(); if(cmd == "START") { logging = true; Serial.println("Logging started"); } else if(cmd == "STOP") { logging = false; Serial.println("Logging paused"); } else if(cmd == "REPORT") { printReport(); } else if(cmd == "RESET") { readCount = 0; ldrMean = 0.0; ldrMin = 1.0; ldrMax = 0.0; tempMean = 0.0; tempMin = 100.0; tempMax = -10.0; Serial.println("Reset complete"); } } } Add bool logging = false; as a global.
9. millis() integration (10 min): in loop(): unsigned long now = millis(); handleSerial(); if(logging && (now - lastReadTime >= 5000)) { lastReadTime = now; takeReading(); } Upload. Test: type "START" — readings begin. Type "STOP" — pause. Type "REPORT" — summary prints. Type "RESET" — clears.
10. printReport() function (15 min): write void printReport() { Serial.println("=== DATA LOGGER REPORT ==="); Serial.print("Total readings: "); Serial.println(readCount); Serial.print("LDR Mean: "); Serial.print(ldrMean, 3); Serial.print(" | Min: "); Serial.print(ldrMin, 3); Serial.print(" | Max: "); Serial.print(ldrMax, 3); Serial.print(" | Range: "); Serial.println(ldrMax - ldrMin, 3); Serial.print("Temp Mean: "); Serial.print(tempMean, 1); Serial.print("C | Min: "); Serial.print(tempMin, 1); Serial.print("C | Max: "); Serial.print(tempMax, 1); Serial.println("C"); } Collect at least 10 live readings, then type "REPORT". Transcribe the output into the Technical System Documentation Sample Output section.
