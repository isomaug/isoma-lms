# Lesson 7: Original Project Design & Build – Build Something Real

**Duration:** 3 hours (Saturday) / 90 min × 3 days (Holiday) (split across Week 7 Lesson 1 start + Lesson 2 finish)
**Term / Week:** Term 1 · Week 7
**Age Range:** 10–12 years
**Group Size:** 8 learners (pair programming, 4 pairs)
**Hardware:** Arduino Uno, USB cable, laptop with Arduino IDE 2.x, selection of components: LEDs, LDR, buzzer, push button, resistors (220Ω and 10kΩ), breadboard, jumper wires (all from kit)
**Bloom's:** L5 Evaluating / L6 Creating
**DDD ILO:** ILO 3.4 – Design, build, test, iterate, and present an original Arduino project that integrates at least one coding concept, one explicit English literacy connection, and one explicit Mathematics connection, supported by a written design brief
**NCDC:** Uganda NCDC P5–P6 – English Strand: Formal writing (design brief and documentation); ICT Strand: Project design, build, and test cycles; Mathematics Strand: Application of sequences, data, and geometry in real-world contexts
**Cambridge:** Cambridge Primary Computing 0845 – Stage 5: Design and make; programming with purpose; iterative development; peer review

**Big Idea:** Real engineers do not start with code. They start with a problem, a user, and a plan. Your design brief is the most important document you will write this term.

## Learning Objectives

- Complete a full 7-section written design brief: Problem Statement, Target User, Solution Description, How It Works (step-by-step), Components List, English/Math Connection, Test Results and Improvements Made
- Build a working Arduino prototype that responds to at least one input and produces at least one output
- Write and upload an Arduino sketch from scratch (not copied) that implements the core function of the project
- Test the prototype against the design brief requirements and document at least one improvement made during testing
- Participate in a structured peer review session using a 5-question rubric and provide written feedback to a partner
- Prepare a 5-minute Demo Day presentation rehearsal: Problem → Solution → Live Demo → Evidence → Reflection

## Materials and Preparation

- 4 laptops with Arduino IDE 2.x
- 4 Arduino Uno boards + USB cables

## Cross-Curricular Links

**English:** Design brief writing as formal technical English: all 7 sections of the design brief must be written in full sentences. The "How It Works" section must use numbered steps. The "English Connection" section must name a specific English literacy skill the project demonstrates (e.g. "My project displays a countdown – this is a sequence, like the sequence of events in a story"). Peer review written feedback must be specific and evidence-based: "Your design brief is clear because…" not just "It is good." This develops the formal writing register required at upper primary and secondary level.

**Maths:** The design brief must include a named Mathematics connection. Acceptable examples: a sensor project with statistical analysis (mean, range); a sequence or pattern generated by a loop (arithmetic sequence, times table); a geometry/measurement calculation used in the physical build (area, perimeter, angles); a counter or timer that involves arithmetic. Learners must show a calculation or graph in the Test Results section that demonstrates the mathematical element.

## Lesson Structure

### SESSION 1 / DAY 1 – Design First, Build Nothing Yet  (60 min)
1. Full component kit per pair: LEDs (red, green, yellow), LDR, buzzer, push button, 220Ω and 10kΩ resistors, breadboard, 20 jumper wires
2. Printed design brief template (A4, 2 pages per learner) – 7 labelled sections with word-count guidance per section
3. Printed peer review rubric (A4 per learner) – 5 questions, 4-point scale each, space for written comments
4. Printed component reference card (A5 per pair) – wiring diagrams for each component in the kit
5. Squared paper (A4, 2 sheets per learner) – for circuit sketching before building
6. Ruler, pencil, pen
7. USB flash drives
8. Facilitator device + projected screen

### SESSION 2 / DAY 2 – Build and First Test  (60 min)
9. Open brief introduction (10 min): facilitator reads the open project brief aloud: "Build an Arduino project that connects coding, English or Maths, and a real-world need you have noticed." Emphasise: the best projects solve a real problem. Examples from Uganda context: a light alarm for studying in the evening when power cuts happen; a timer for cooking; a noise alert; an automatic plant watering reminder.
10. Brainstorm (10 min): each learner individually writes 3 project ideas on a sticky note. Pairs share and choose one together. Ideas must be achievable with the available component kit.
11. Design brief Section 1 – Problem Statement (10 min): write 1 paragraph (3–5 sentences) describing the real problem the project addresses. Must name: who has this problem, when it happens, and why it matters.
12. Design brief Section 2 – Target User (5 min): write 2–3 sentences describing the person who will benefit from this project. Be specific: "A P6 student who studies at home in the evening when UMEME power cuts happen."
13. Design brief Section 3 – Solution Description (10 min): describe the project in 3–5 sentences. What does it do? What happens when it is turned on? What is the output the user sees or hears?
14. Design brief Section 4 – How It Works (10 min): write numbered steps describing the programme logic. This is pseudocode written as plain English instructions. Each step will become one block of code later.
15. Design brief Section 5 – Components List (5 min): list every component needed. Pair checks: is each component available in the kit? If a component is not available, the design must be revised.
16. Circuit sketch (10 min): before touching any component, draw the circuit on squared paper. Label every pin connection. Pair checks: does the sketch match the component reference card? Facilitator approves the sketch before the build begins.

### SESSION 3 / DAY 3 – Iterate, Peer Review, Rehearse  (50 min)
17. Build the circuit (20 min): following the sketch, assemble the circuit on the breadboard. Facilitator checks all builds before USB connection.
18. Write the sketch (20 min): open Arduino IDE, write the sketch from scratch following the "How It Works" numbered steps from the design brief. Each step in the design brief must correspond to identifiable lines of code. No copy-paste from previous weeks; learners write from their plan.
19. First test (10 min): upload and test. Does the project behave as described in the design brief? Pairs record: "What worked? What did not work?" on the Test Results section of the brief.
20. First iteration: if the project does not work, trace through the code step by step. Is the circuit wired correctly? Is there a logic error? Is there a syntax error? Make one change at a time.
21. Iteration and final testing (15 min): implement at least one improvement based on yesterday's test. Document it in the "Improvements Made" part of the Test Results section. Complete the Mathematics element: ensure at least one calculation or graph is present in the Test Results.
22. Complete design brief Sections 6 and 7 (10 min): Section 6 – English/Math Connection: write 2 sentences each naming the specific skill and explaining how the project demonstrates it. Section 7 – Test Results and Improvements Made: describe 2 tests and the result of each, plus one documented improvement.
23. Peer review session (15 min): swap design briefs with the partner pair. Each learner completes the 5-question peer review rubric for their partner's design brief. Questions: (1) Is the problem clearly described? (2) Is the "How It Works" section detailed enough to follow? (3) Is the English connection specific and real? (4) Is the Math connection demonstrated with a calculation or graph? (5) Is the writing clear and in full sentences? Write one specific written comment per question.
24. Presentation rehearsal (10 min): each learner practises the 5-minute structure aloud to their partner: Problem → Solution → Live Demo → Evidence (show the math/English element) → Reflection (what I would improve next). Partner gives 1 Star + 1 Wish.

### SHOWCASE & DEBRIEF  (30 min)
25. 2 pairs give a full rehearsal presentation (5 minutes each). Class observes and takes notes using the peer review rubric.
26. Facilitator gives whole-class feedback: "Three things I saw well across all projects today: ___, ___, ___. One thing everyone should strengthen before Demo Day: ___."
27. Facilitator connects to the DDD ILO: "ILO 3.4 asks you to design, build, test, iterate, and present. You have done all five this week. Demo Day is your chance to show the finished version."
28. Remind learners of Demo Day requirements: working prototype + written design brief + 5-minute presentation + peer review rubric completed for a classmate.
29. Remind learners of DDD assessment weights: prototype functionality 10%, code quality 10%, integration 10%, presentation 20%, written design brief 10%.
30. Collect completed design briefs for facilitator review. Return with written comments before Demo Day.
31. Submit sketches and design briefs via USB flash drive.

## Assessment

- Formative | (During) | Circuit sketch approved by facilitator before building (physical check, Session 2) | Design brief Sections 1–5 complete by end of Session 1 (facilitator review) | First test documented in Test Results section (checked during Session 2) | Peer review rubric completed with specific written comments per question (collected, Session 3)
- Exit Assessment | Working prototype: responds to at least one input, produces at least one output (verified by facilitator) | Complete written design brief: all 7 sections present, written in full sentences (submitted, assessed on 5-point rubric) | Peer review rubric: all 5 questions answered with written comments (submitted) | Presentation rehearsal completed: 5-minute structure attempted with partner (observed by facilitator)
- Differentiation | Support: Provide a pre-built simple circuit (LED + push button) and a basic sketch template. Learner focuses on completing the design brief fully and connecting the project to a real problem. For peer review, provide sentence starters: "The problem is clearly described because…" "One thing that could be clearer is…" | Extension: Add a second sensor or a second LED output to increase project complexity. Write a function for each major behaviour and call them from loop(). Add a Serial Monitor display that prints a summary of the project's decisions: "Light detected – LED ON", "Button pressed – Buzzer activated". Calculate efficiency: how many loop() iterations per minute? How does this compare to doing the same task by hand?

## Key Vocabulary

design brief · prototype · iteration · test cycle · peer review · breadboard · component · input · output · debugging · evidence · reflection

## Safeguarding

Safeguarding Note: All project ideas must be appropriate for a school setting. Projects that simulate alarms, surveillance, or monitoring of other people must be discussed with the facilitator before building. Remind learners: a circuit must always be checked before power is connected. Never connect more than 5V to any component without facilitator approval. All personal details in any design brief section must use first name only.
