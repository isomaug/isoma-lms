# Week 7 - Lesson 1

## Session length
**About half of this week's plan** (you will finish in Lesson 2)

## Today you will learn
- Complete a full 7-section written design brief: Problem Statement, Target User, Solution Description, How It Works (step-by-step), Components List, English/Math Connection, Test Results and Improvements Made
- Build a working Arduino prototype that responds to at least one input and produces at least one output
- Write and upload an Arduino sketch from scratch (not copied) that implements the core function of the project
- Test the prototype against the design brief requirements and document at least one improvement made during testing
- Participate in a structured peer review session using a 5-question rubric and provide written feedback to a partner
- Prepare a 5-minute Demo Day presentation rehearsal: Problem -> Solution -> Live Demo -> Evidence -> Reflection

## Big idea
Real engineers do not start with code. They start with a problem, a user, and a plan. Your design brief is the most important document you will write this term.

## What you need
- 4 laptops with Arduino IDE 2.x
- 4 Arduino Uno boards + USB cables

## Links to English and Maths
- **English:** Design brief writing as formal technical English: all 7 sections of the design brief must be written in full sentences. The "How It Works" section must use numbered steps. The "English Connection" section must name a specific English literacy skill the project demonstrates (e.g. "My project displays a countdown – this is a sequence, like the sequence of events in a story"). Peer review written feedback must be specific and evidence-based: "Your design brief is clear because…" not just "It is good." This develops the formal writing register required at upper primary and secondary level.
- **Maths:** The design brief must include a named Mathematics connection. Acceptable examples: a sensor project with statistical analysis (mean, range); a sequence or pattern generated by a loop (arithmetic sequence, times table); a geometry/measurement calculation used in the physical build (area, perimeter, angles); a counter or timer that involves arithmetic. You must show a calculation or graph in the Test Results section that demonstrates the mathematical element.

## Let's begin

### SESSION 1 / DAY 1 – Design First, Build Nothing Yet  (60 min)
1. Full component kit for you: LEDs (red, green, yellow), LDR, buzzer, push button, 220Ω and 10kΩ resistors, breadboard, 20 jumper wires
2. Printed design brief template (A4, 2 pages for you) – 7 labelled sections with word-count guidance per section
3. Printed peer review rubric (A4 for you) – 5 questions, 4-point scale each, space for written comments
4. Printed component reference card (A5 for you) – wiring diagrams for each component in the kit
5. Squared paper (A4, 2 sheets for you) – for circuit sketching before building
6. Ruler, pencil, pen
7. USB flash drives
8. A computer screen to follow along

### SESSION 2 / DAY 2 – Build and First Test  (60 min)
9. Open brief introduction (10 min): you read the open project brief aloud: "Build an Arduino project that connects coding, English or Maths, and a real-world need you have noticed." Emphasise: the best projects solve a real problem. Examples from Uganda context: a light alarm for studying in the evening when power cuts happen; a timer for cooking; a noise alert; an automatic plant watering reminder.
10. Brainstorm (10 min): you individually writes 3 project ideas on a sticky note. You share and choose one together. Ideas must be achievable with the available component kit.
11. Design brief Section 1 – Problem Statement (10 min): write 1 paragraph (3–5 sentences) describing the real problem the project addresses. Must name: who has this problem, when it happens, and why it matters.
12. Design brief Section 2 – Target User (5 min): write 2–3 sentences describing the person who will benefit from this project. Be specific: "A P6 student who studies at home in the evening when UMEME power cuts happen."
13. Design brief Section 3 – Solution Description (10 min): describe the project in 3–5 sentences. What does it do? What happens when it is turned on? What is the output the user sees or hears?
14. Design brief Section 4 – How It Works (10 min): write numbered steps describing the programme logic. This is pseudocode written as plain English instructions. Each step will become one block of code later.
15. Design brief Section 5 – Components List (5 min): list every component needed. Pair checks: is each component available in the kit? If a component is not available, the design must be revised.
