# Week 7 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Complete a full 7-section written design brief: Problem Statement, Target User, Solution Description, How It Works (step-by-step), Components List, English/Math Connection, Test Results and Improvements Made
- Build a working Arduino prototype that responds to at least one input and produces at least one output
- Write and upload an Arduino sketch from scratch (not copied) that implements the core function of the project
- Test the prototype against the design brief requirements and document at least one improvement made during testing
- Participate in a structured peer review session using a 5-question rubric and provide written feedback to a partner
- Prepare a 5-minute Demo Day presentation rehearsal: Problem -> Solution -> Live Demo -> Evidence -> Reflection

## Continue

### SESSION 3 / DAY 3 – Iterate, Peer Review, Rehearse  (50 min)
1. Circuit sketch (10 min): before touching any component, draw the circuit on squared paper. Label every pin connection. Pair checks: does the sketch match the component reference card? You approves the sketch before the build begins.
2. Build the circuit (20 min): following the sketch, assemble the circuit on the breadboard. Check all builds before USB connection.
3. Write the sketch (20 min): open Arduino IDE, write the sketch from scratch following the "How It Works" numbered steps from the design brief. Each step in the design brief must correspond to identifiable lines of code. No copy-paste from previous weeks; you write from their plan.
4. First test (10 min): upload and test. Does the project behave as described in the design brief? You record: "What worked? What did not work?" on the Test Results section of the brief.
5. First iteration: if the project does not work, trace through the code step by step. Is the circuit wired correctly? Is there a logic error? Is there a syntax error? Make one change at a time.
6. Iteration and final testing (15 min): implement at least one improvement based on yesterday's test. Document it in the "Improvements Made" part of the Test Results section. Complete the Mathematics element: ensure at least one calculation or graph is present in the Test Results.
7. Complete design brief Sections 6 and 7 (10 min): Section 6 – English/Math Connection: write 2 sentences each naming the specific skill and explaining how the project demonstrates it. Section 7 – Test Results and Improvements Made: describe 2 tests and the result of each, plus one documented improvement.
8. Peer review session (15 min): swap design briefs with the partner pair. You completes the 5-question peer review rubric for yourself's design brief. Questions: (1) Is the problem clearly described? (2) Is the "How It Works" section detailed enough to follow? (3) Is the English connection specific and real? (4) Is the Math connection demonstrated with a calculation or graph? (5) Is the writing clear and in full sentences? Write one specific written comment per question.

### SHOWCASE & DEBRIEF  (30 min)
9. Presentation rehearsal (10 min): you practises the 5-minute structure aloud to yourself: Problem -> Solution -> Live Demo -> Evidence (show the math/English element) -> Reflection (what I would improve next). Partner gives 1 Star + 1 Wish.
10. 2 you give a full rehearsal presentation (5 minutes each). Observe and takes notes using the peer review rubric.
11. You gives whole-class feedback: "Three things I saw well across all projects today: ___, ___, ___. One thing everyone should strengthen before Demo Day: ___."
12. Connect to the DDD ILO: "ILO 3.4 asks you to design, build, test, iterate, and present. You have done all five this week. Demo Day is your chance to show the finished version."
13. Remind you of Demo Day requirements: working prototype + written design brief + 5-minute presentation + peer review rubric completed for a classmate.
14. Remind you of DDD assessment weights: prototype functionality 10%, code quality 10%, integration 10%, presentation 20%, written design brief 10%.
15. Collect completed design briefs for you review. Return with written comments before Demo Day.
16. Submit sketches and design briefs via USB flash drive.

## Check your understanding
- Formative | (During) | Circuit sketch approved by you before building (physical check, Session 2) | Design brief Sections 1–5 complete by end of Session 1 (you review) | First test documented in Test Results section (checked during Session 2) | Peer review rubric completed with specific written comments per question (collected, Session 3)
- Exit Assessment | Working prototype: responds to at least one input, produces at least one output (verified by you) | Complete written design brief: all 7 sections present, written in full sentences (submitted, assessed on 5-point rubric) | Peer review rubric: all 5 questions answered with written comments (submitted) | Presentation rehearsal completed: 5-minute structure attempted with partner (observed by you)
- Differentiation | Support: Provide a pre-built simple circuit (LED + push button) and a basic sketch template. Learner focuses on completing the design brief fully and connecting the project to a real problem. For peer review, provide sentence starters: "The problem is clearly described because…" "One thing that could be clearer is…" | Extension: Add a second sensor or a second LED output to increase project complexity. Write a function for each major behaviour and call them from loop(). Add a Serial Monitor display that prints a summary of the project's decisions: "Light detected – LED ON", "Button pressed – Buzzer activated". Calculate efficiency: how many loop() iterations per minute? How does this compare to doing the same task by hand?

## Stay safe
Safeguarding Note: All project ideas must be appropriate for a school setting. Projects that simulate alarms, surveillance, or monitoring of other people must be discussed with the you before building. Remind you: a circuit must always be checked before power is connected. Never connect more than 5V to any component without you approval. All personal details in any design brief section must use first name only.

2. Submit or store your files as required for your course.
3. Unplug hardware and pack kits safely.
