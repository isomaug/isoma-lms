# Lesson 2: Read & Code – Code Comprehension

**Duration:** 60 minutes (split across Week 2 Lesson 1 start + Lesson 2 finish)
**Term / Week:** Term 1 · Week 2
**Age Range:** 8–10 years
**Hardware:** BBC Micro:bit v2, USB cable, shared laptops
**Bloom's:** L3 Applying
**DDD Phase:** DELIVER – Learners read existing code as structured text, predict outcomes, then modify and run

**Big Idea:** Reading code is like reading instructions – you must understand what is written before you change it. Good programmers read first, code second.

## Learning Objectives

- Read a provided MakeCode block programme and predict what it will do before running it
- Answer 5 code comprehension questions (what it does, input, output, first action, possible error)
- Identify all numerical values in the code and state their units (milliseconds, pixels)
- Modify one value in the programme (e.g. change display number or delay time) and confirm the change works
- Explain why reading code carefully before changing it matters

## Materials and Preparation

- 4 BBC Micro:bit v2 kits with USB cables
- Printed 'Read This Code' worksheet (A4) – screenshot of a completed MakeCode programme with labels
- Code comprehension question sheet (5 questions): What does this do? What is the input? What is the output? What happens first? What could go wrong?
- Pencils and highlighters
- A screen or device to show the MakeCode programme

## Cross-Curricular Links

**English:** Reading comprehension: read the programme as a text. Answer 5 structured questions about it. Reading code is like reading instructions – you must understand before you change. Write one sentence explaining what the code does.

**Maths:** Identify all numerical values in the code. What are the units? Change the delay from 500 ms to 1000 ms – what is that in seconds? Unit conversion: 1000 ms = 1 second. Calculate: 2500 ms = ? seconds; 750 ms = ? seconds.

## Lesson Structure

### HOOK – Can You Read Code?
1. Look at a MakeCode programme on screen (example: on start → show number 7 → pause 500ms → show number 14 → pause 500ms → forever). Do **not** run it yet.
2. Without touching the device, predict: What will this programme do? What numbers will appear? In what order?
3. Write your prediction. You will check if you were right after you run it.
4. Remember: reading code is like reading a recipe – understand all steps before you start.

### DESIGN – Read Before You Run
5. Open the printed 'Read This Code' worksheet and the comprehension question sheet.
6. Read the printed programme carefully. Highlight: circle all numbers in one colour, underline all actions in another.
7. Answer the 5 comprehension questions in full sentences:
   - What does this do?
   - What is the input?
   - What is the output?
   - What happens first?
   - What could go wrong?

### DELIVER – Build and run (start)
8. Open MakeCode and recreate the programme from the worksheet.
9. **Step 1:** Download and run it. Was your prediction correct? Circle YES / PARTLY / NO and write one sentence explaining any difference.
10. **Step 2:** Change the pause from 500 ms to 1000 ms. Before downloading, answer: how long will the number now show? (1 second). Re-download and confirm.

### DELIVER – Modify and explain (finish)
1. **Step 3:** Change the numbers displayed (for example 7 → 21, 14 → 42). Predict: what pattern are you creating? Download and confirm.
2. **Step 4:** Read each block aloud before you change anything else.

### DISCOVER – Debrief
3. Compare the original programme with your first prediction. What did you get right?
4. Write: one thing you understood before running / one thing that surprised you.
5. Maths check: 500 ms is how many seconds? 2000 ms? 1500 ms?

### Coming next week
Next week you will make the Micro:bit count using **loops** that repeat automatically.

### WRAP-UP
6. Save your project in MakeCode as `Week2_[YourInitials]`.
7. Tick: comprehension questions answered / modification made / prediction written.
8. Unplug and store the Micro:bit kit safely.

## Assessment

- Comprehension worksheet (5 questions) completed in full sentences
- Modified programme runs correctly with the intended change
- Exit check: If I change a delay from 500 ms to 2000 ms, what is the new delay in seconds? (Answer: 2 seconds)
