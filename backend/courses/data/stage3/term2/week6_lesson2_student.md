# Week 6 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Use the MakeCode JavaScript toggle (the '{} JavaScript' button) to switch between block view and text view of an existing programme
- Read the JavaScript of their T2 Week 5 Integration Sprint project line by line and annotate each function and variable with a plain-English comment
- Identify and explain 5 JavaScript keywords or structures: 'basic.onStart', 'input.onButtonPressed', 'let', 'if/else', and 'basic.showNumber'
- Answer 5 written JavaScript comprehension questions about a provided code snippet (what does this line do? what is the input? what changes if this number is altered?)
- Make one specific text-level modification — change a value, a string, or a threshold number directly in JavaScript view — and verify it changes the programme's output
- Explain in one sentence why reading the text view of code is a useful skill, even for block-based programmers

## Continue

### DELIVER – Toggle, Annotate, and Modify (28 min)
1. Step 1 – Explore the toggle (5 min): Driver clicks '{} JavaScript'. Both you read the code silently. Navigator identifies the variable declaration line ('let') and highlights it. Driver identifies the if/else block and highlights it.
2. Step 2 – Annotate own code (10 min): you opens a text editor alongside MakeCode and writes a comment for every line of their own project's JavaScript — at least 8 lines annotated. Must include the variable, the condition, and one sensor input line.
3. Step 3 – One text modification (8 min): Continue with the next steps yourself. New Driver changes ONE value directly in the JavaScript text view (e.g. changes a threshold number, a pause duration, or a display string). Predict: what will change? Switch back to block view to verify. Download and run.
4. Step 4 – Verify the change (5 min): confirm the behaviour changed as predicted. If not — debug by tracing the JavaScript line by line. Record: 'I changed ___ from ___ to ___. The programme now ___.'
### DISCOVER – Share and Reflect (8 min)
5. Two you share their annotated code on screen. They read two consecutive lines aloud and explain what each does. Class confirms or corrects the annotation.
6. Ask yourself: 'What is ONE thing that was EASIER to understand in block view? What is ONE thing that was EASIER to understand in JavaScript view?' Take 4 responses. Build a 2-column comparison on the board: Blocks | JavaScript.
7. Evaluative reflection: you writes their one-sentence evaluation on the back of the annotation worksheet: 'Reading the JavaScript view helps me because ___.' Read 3 aloud (anonymously) to close.
### WRAP-UP – Save and Collect (2 min)
8. Rename updated MakeCode project 'T2W6_[Name]_JS'. Disconnect Micro:bit.
9. Collect JavaScript annotation worksheets and comprehension question sheets. The annotated worksheet is this week's formally assessed artifact. You checks: minimum 8 annotated lines and one identified text-level modification recorded.

## Check your understanding
- Formative (During)
- Observation: Can learner toggle between block and JavaScript views confidently without confusion? (navigation check)
- Are at least 8 lines of own programme annotated with plain-English comments? (annotation worksheet check)
- 5 JavaScript comprehension questions answered in full sentences? (question sheet check)
- One text-level modification made, predicted, and verified against actual output? (modification check)
- Exit Assessment
- You shows 3 JavaScript lines on screen (one at a time) and asks you: 'What does this line do?' Lines chosen from: a variable declaration, a condition threshold, and a basic.pause value. Learner answers in one sentence each. 3 points for you. Record on assessment log — this is the week's formal artifact grade.
- Differentiation
- Support: Reduce the annotation task to 5 lines (pre-highlight the remaining lines for the learner). Provide a word bank of annotation phrases: 'This line sets…', 'This line checks…', 'This line displays…', 'This line waits…'. Allow the learner to annotate in block view first, then match annotations to JavaScript lines. Extension: Write a brand-new 3-line JavaScript function directly in text view without using blocks at all (e.g. display a string on start). Test and verify it compiles. Compare: which felt harder — blocks or text? Write a paragraph explaining why.
