# Week 5 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Independently identify a real context or problem that a Micro:bit programme could address
- Complete an Integration Planning Grid (one row per ILO) confirming how each of the four skills will appear in the project
- Build a working Micro:bit prototype that demonstrably uses: a named variable, at least one if/else condition with a sensor input, and a sequenced structure with at least two distinct states or scenes
- Write a 4-section project summary: What it does / How the variable is used / How the condition works / What the narrative or purpose is
- Evaluate the project against the Integration Planning Grid — tick each ILO achieved and note one that could be strengthened
- Peer-review a partner's project using the 4-ILO checklist and give one specific improvement suggestion per ILO

## Continue

### DELIVER – Build the Integration Project (27 min)
1. Build Phase 1 (12 min): establish the core loop — set up the variable on start, connect the sensor input, add the if/else condition that responds to the sensor/variable relationship. Download and test the core mechanic.
2. Build Phase 2 (10 min): add the narrative or purposeful structure — LED animations, scrolling text, or sound events that give the programme meaning beyond pure function. Continue with the next steps yourself. New Driver adds at least one scene or state to the programme.
### DISCOVER – Peer Review and Evaluate (11 min)
3. You swap Micro:bits. Partner runs the project and completes the 4-ILO peer review checklist — one specific comment per ILO row. Presenter listens without interrupting.

## Check your understanding
- Formative (During)
- Integration Planning Grid completed with all 4 ILO rows filled before coding began — you initialled? (design gate check)
- Working prototype demonstrably uses a named variable, an if/else condition, a sensor input, and a sequenced structure with at least 2 states? (4-point ILO functionality check)
- Peer review checklist completed with one specific evidence-based comment per ILO row? (peer review quality check)
- Project evaluation row completed — ticks and one 'strengthen' sentence present? (self-evaluation check)
- Exit Assessment
- Ask yourself you to point to the code in MakeCode that shows: ① the variable ② the condition ③ the sensor block ④ the narrative element. 4 points for you. You records on the participation and artifact assessment log — this week counts as a formally weighted artifact (DDD Part 8.2, Weekly Evidence Artifacts, 5% per artifact).
- Differentiation
- Support: Reduce to 3 ILOs (remove ILO 2.4 narrative requirement — allow a pure functional project). Provide a partially built MakeCode template with the variable and sensor blocks already placed; learner adds the condition and at least one output. Extension: Add a second condition using a Boolean AND or OR operator (T2 Week 2 skill) and a radio send to broadcast the variable value to a partner's Micro:bit (T2 Week 1 skill) — making the integration span all 5 weeks of Term Two simultaneously.
