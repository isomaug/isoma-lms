# Week 5 - Lesson 1

## Session length
**About half of this week's plan** (you will finish in Lesson 2)

## Today you will learn
- Independently identify a real context or problem that a Micro:bit programme could address
- Complete an Integration Planning Grid (one row per ILO) confirming how each of the four skills will appear in the project
- Build a working Micro:bit prototype that demonstrably uses: a named variable, at least one if/else condition with a sensor input, and a sequenced structure with at least two distinct states or scenes
- Write a 4-section project summary: What it does / How the variable is used / How the condition works / What the narrative or purpose is
- Evaluate the project against the Integration Planning Grid — tick each ILO achieved and note one that could be strengthened
- Peer-review a partner's project using the 4-ILO checklist and give one specific improvement suggestion per ILO

## Big idea
The best programmes combine many ideas working together. A variable tracks something. A condition makes a decision about it. A sensor brings the real world in. A story gives it meaning. When these four work together, you have a real system — not just a collection of blocks.

## What you need
- 4 BBC Micro:bit v2 kits + USB cables
- 4 shared laptops with MakeCode open
- Integration Planning Grid (A4 for you) – 4 rows: ILO 2.1 Variable | ILO 2.2 Condition | ILO 2.3 Sensor | ILO 2.4 Narrative; 3 columns: What I will use / How / Evidence
- 4-section project summary template (A4 for you)
- Peer review checklist (A5 for you) – 4 ILO rows with space for 1 comment per ILO
- Sticky notes for bug log during build phase
- Vocabulary reference card (A5, cumulative – all key terms from T1 and T2 Weeks 1–4)
- A computer or screen to follow along
- 'One Star, One Wish' cards for peer gallery share

## Links to English and Maths
- **English:** Structured project writing: you complete the 4-section project summary in full sentences. Each section must contain at least 2 sentences. Section prompts: ① 'My project does…' ② 'The variable in my project is called ___ and it tracks…' ③ 'The condition in my programme checks ___ and responds by…' ④ 'The purpose or story of my project is…'. Peer review writing: the 4-ILO checklist requires a specific, evidence-based comment for each ILO — one sentence minimum. Oral explanation: you presents their project summary to their partner in exactly 60 seconds.
- **Maths:** Applied integration: learner must explicitly identify the mathematical element within their project. Possible examples: a variable that counts from 0 and the learner calculates when it will reach a target (counting on / multiplication), a temperature threshold value chosen based on a calculation (e.g. body temperature is 37°C, so the alarm fires at 36°C), a timing sequence where scene durations are planned and summed to a total, or a light sensor threshold derived from comparing two readings from T2 Week 3 data. Learner writes the mathematical element explicitly in Section 2 or 3 of the project summary with a number or calculation shown.

## Let's begin

### HOOK – Four Skills, One Project (8 min)
1. No new concepts today. Open by recapping T2 Weeks 1–4 on the board as four columns: Variable | Condition | Sensor | Narrative. Ask: 'Can anyone name one thing we built for each of these in the last four weeks?' Take one answer per column.
2. Show a pre-built integration example on the projected Micro:bit simulator: a programme where shaking the device (sensor) increments a 'steps' variable (variable), which triggers a congratulations animation when it reaches 10 (condition), telling the story of a character reaching the finish line (narrative). Walk through each element briefly.
3. Introduce the challenge: 'Today you have 27 minutes to build your own project that uses ALL FOUR skills. The planning grid is your contract. You cannot start coding until the grid is complete.'
### DESIGN – Complete the Integration Planning Grid (12 min)
4. Get ready to use Integration Planning Grids. You complete all four rows INDEPENDENTLY before any pair discussion. Check your work carefully: 'What will your variable be called? What does it track? Which sensor are you using and why?'
5. You share grids with each other. Partner checks: 'Does Row 3 (sensor) actually connect to Row 2 (condition)? Is the narrative in Row 4 something the code will actually express?' You refine if needed.
6. You approval gate: every pair must have a signed-off grid before laptops are distributed. You initials the grid. Any project that does not include all four ILOs is redirected — prompt: 'Where is your variable? Where is your condition?'
7. You begin the 4-section project summary title and Section 1 on paper while waiting for laptops.
### DELIVER – Build the Integration Project (27 min)
8. Get ready to use Micro:bits and laptops. Assign Driver and Navigator. Navigator holds the planning grid and monitors ILO coverage throughout — their explicit role is to call out if an ILO is missing from the code.
