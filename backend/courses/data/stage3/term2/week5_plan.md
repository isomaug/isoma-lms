# Lesson 13: Integration Sprint – All Four Skills in One Project

**Duration:** 60 minutes (split across Week 5 Lesson 1 start + Lesson 2 finish)
**Term / Week:** Term 2 · Week 5
**Age Range:** 8–10 years
**Hardware:** BBC Micro:bit v2 + USB cables + shared laptops
**Software:** Microsoft MakeCode (makecode.microbit.org)
**Bloom's:** L4–L6 Analysing / Evaluating / Creating
**DDD Phase:** DELIVER → DISCOVER – Learners combine all four ILOs (variables, logic, sensors, narrative) in one self-directed mini-project, demonstrating integrated mastery
**NCDC:** Uganda NCDC P3–P4: ICT Literacy Strand; Numeracy Strand – Patterns, Logic & Data
**Cambridge:** Cambridge Primary Computing 0845 – Stage 3: Designing programmes that combine multiple concepts; Selecting appropriate tools and structures; Evaluating own solutions against stated criteria

**Big Idea:** The best programmes combine many ideas working together. A variable tracks something. A condition makes a decision about it. A sensor brings the real world in. A story gives it meaning. When these four work together, you have a real system — not just a collection of blocks.

**Source plan:** `Stage3_Term2_Week5_Microbit_LessonPlan.docx`

## Learning Objectives

- Independently identify a real context or problem that a Micro:bit programme could address
- Complete an Integration Planning Grid (one row per ILO) confirming how each of the four skills will appear in the project
- Build a working Micro:bit prototype that demonstrably uses: a named variable, at least one if/else condition with a sensor input, and a sequenced structure with at least two distinct states or scenes
- Write a 4-section project summary: What it does / How the variable is used / How the condition works / What the narrative or purpose is
- Evaluate the project against the Integration Planning Grid — tick each ILO achieved and note one that could be strengthened
- Peer-review a partner's project using the 4-ILO checklist and give one specific improvement suggestion per ILO

## Materials and Preparation

- 4 BBC Micro:bit v2 kits + USB cables
- 4 shared laptops with MakeCode open
- Integration Planning Grid (A4 per learner) – 4 rows: ILO 2.1 Variable | ILO 2.2 Condition | ILO 2.3 Sensor | ILO 2.4 Narrative; 3 columns: What I will use / How / Evidence
- 4-section project summary template (A4 per learner)
- Peer review checklist (A5 per learner) – 4 ILO rows with space for 1 comment per ILO
- Sticky notes for bug log during build phase
- Vocabulary reference card (A5, cumulative – all key terms from T1 and T2 Weeks 1–4)
- Facilitator device + projected screen
- 'One Star, One Wish' cards for peer gallery share

## Cross-Curricular Links

**English:** Structured project writing: learners complete the 4-section project summary in full sentences. Each section must contain at least 2 sentences. Section prompts: ① 'My project does…' ② 'The variable in my project is called ___ and it tracks…' ③ 'The condition in my programme checks ___ and responds by…' ④ 'The purpose or story of my project is…'. Peer review writing: the 4-ILO checklist requires a specific, evidence-based comment for each ILO — one sentence minimum. Oral explanation: each learner presents their project summary to their partner in exactly 60 seconds.

**Maths:** Applied integration: learner must explicitly identify the mathematical element within their project. Possible examples: a variable that counts from 0 and the learner calculates when it will reach a target (counting on / multiplication), a temperature threshold value chosen based on a calculation (e.g. body temperature is 37°C, so the alarm fires at 36°C), a timing sequence where scene durations are planned and summed to a total, or a light sensor threshold derived from comparing two readings from T2 Week 3 data. Learner writes the mathematical element explicitly in Section 2 or 3 of the project summary with a number or calculation shown.

## Lesson Structure

### HOOK – Four Skills, One Project (8 min)
1. No new concepts today. Open by recapping T2 Weeks 1–4 on the board as four columns: Variable | Condition | Sensor | Narrative. Ask: 'Can anyone name one thing we built for each of these in the last four weeks?' Take one answer per column.
2. Show a pre-built integration example on the projected Micro:bit simulator: a programme where shaking the device (sensor) increments a 'steps' variable (variable), which triggers a congratulations animation when it reaches 10 (condition), telling the story of a character reaching the finish line (narrative). Walk through each element briefly.
3. Introduce the challenge: 'Today you have 27 minutes to build your own project that uses ALL FOUR skills. The planning grid is your contract. You cannot start coding until the grid is complete.'
### DESIGN – Complete the Integration Planning Grid (12 min)
4. Distribute Integration Planning Grids. Learners complete all four rows INDEPENDENTLY before any pair discussion. Facilitator circulates: 'What will your variable be called? What does it track? Which sensor are you using and why?'
5. Pairs share grids with each other. Partner checks: 'Does Row 3 (sensor) actually connect to Row 2 (condition)? Is the narrative in Row 4 something the code will actually express?' Pairs refine if needed.
6. Facilitator approval gate: every pair must have a signed-off grid before laptops are distributed. Facilitator initials the grid. Any project that does not include all four ILOs is redirected — prompt: 'Where is your variable? Where is your condition?'
7. Learners begin the 4-section project summary title and Section 1 on paper while waiting for laptops.
### DELIVER – Build the Integration Project (27 min)
8. Distribute Micro:bits and laptops. Assign Driver and Navigator. Navigator holds the planning grid and monitors ILO coverage throughout — their explicit role is to call out if an ILO is missing from the code.
9. Build Phase 1 (12 min): establish the core loop — set up the variable on start, connect the sensor input, add the if/else condition that responds to the sensor/variable relationship. Download and test the core mechanic.
10. Build Phase 2 (10 min): add the narrative or purposeful structure — LED animations, scrolling text, or sound events that give the programme meaning beyond pure function. SWAP Driver and Navigator. New Driver adds at least one scene or state to the programme.
### DISCOVER – Peer Review and Evaluate (11 min)
11. Pairs swap Micro:bits. Partner runs the project and completes the 4-ILO peer review checklist — one specific comment per ILO row. Presenter listens without interrupting.
12. Partner returns Micro:bit and reads their checklist aloud. Learner responds: 'For ILO ___, I agree/disagree because ___. The change I will make is ___.'
13. Each learner completes the project evaluation row at the bottom of their planning grid: tick each ILO achieved and write one sentence naming the ILO they would strengthen with more time.
14. Gallery rapid-share: each pair holds up their Micro:bit and says one sentence — 'Our project combines ___, ___, ___, and ___ to ___.' Facilitator notes which projects demonstrate the cleanest ILO integration for the assessment record.
### WRAP-UP – Save and Collect (2 min)
15. Rename MakeCode project 'T2W5_[Name]_Integration'. Disconnect Micro:bit and return to kit box.
16. Collect Integration Planning Grids, 4-section project summaries, and peer review checklists. All three are formally assessed. Facilitator notes which learners are on track for the Term Two Demo Day in Week 16.

## Assessment

- Formative (During)
- Integration Planning Grid completed with all 4 ILO rows filled before coding began — facilitator initialled? (design gate check)
- Working prototype demonstrably uses a named variable, an if/else condition, a sensor input, and a sequenced structure with at least 2 states? (4-point ILO functionality check)
- Peer review checklist completed with one specific evidence-based comment per ILO row? (peer review quality check)
- Project evaluation row completed — ticks and one 'strengthen' sentence present? (self-evaluation check)
- Exit Assessment
- Facilitator asks each learner to point to the code in MakeCode that shows: ① the variable ② the condition ③ the sensor block ④ the narrative element. 4 points per learner. Facilitator records on the participation and artifact assessment log — this week counts as a formally weighted artifact (DDD Part 8.2, Weekly Evidence Artifacts, 5% per artifact).
- Differentiation
- Support: Reduce to 3 ILOs (remove ILO 2.4 narrative requirement — allow a pure functional project). Provide a partially built MakeCode template with the variable and sensor blocks already placed; learner adds the condition and at least one output. Extension: Add a second condition using a Boolean AND or OR operator (T2 Week 2 skill) and a radio send to broadcast the variable value to a partner's Micro:bit (T2 Week 1 skill) — making the integration span all 5 weeks of Term Two simultaneously.

## Safeguarding

Safeguarding Note: Project ideas must be positive and constructive. Facilitator reviews all integration planning grids during the approval gate step and redirects any project concept that involves monitoring individuals, imitating surveillance, or producing content that could embarrass or exclude a classmate. All peer review comments must be respectful and evidence-based — facilitator reads all completed checklists before returning them.
