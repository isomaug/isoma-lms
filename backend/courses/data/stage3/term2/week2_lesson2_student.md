# Week 2 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Trace a provided MakeCode programme with nested if/else conditions on paper and write the predicted output for 3 different inputs
- Explain the difference between AND (both conditions must be true) and OR (at least one condition must be true) using a real-world example
- Code a programme that uses AND: if temperature > 25 AND button A is pressed -> show sun icon; otherwise -> show moon icon
- Code a programme that uses OR: if button A is pressed OR the Micro:bit is shaken -> show star icon; otherwise -> show dot
- Design a 3-decision system using at least 2 sensors and one Boolean operator, documented in a logic flow diagram on paper before coding
- Identify and fix 2 logic errors in a provided broken programme using the trace method

## Continue

### DELIVER – Code Three Systems (30 min)
1. Task 1 – AND condition (10 min): Code 'forever': if temperature > 25 AND button A is pressed -> show icon 'sun'; else -> show icon 'moon'. Locate the AND block in the Logic category. Download and test: press Button A in a warm hand. Does the sun appear only when BOTH conditions are met?
2. Task 2 – OR condition (8 min): Code 'on button A pressed OR on shake': show icon 'star'; else -> show icon 'small dot'. Test: shake the Micro:bit, then press Button A. Does the star appear for EITHER action?
3. Task 3 – Own 3-decision system (8 min): you code the system from their logic flow diagram. Must use at least 2 sensors and one Boolean operator. Continue with the next steps yourself for this task.
4. Trace check (4 min): return to the trace worksheet. You fill in 'Actual Output' for all 3 inputs by running the printed programme on their Micro:bit. Compare prediction vs. actual. Circle any differences and discuss why.
### DISCOVER – Debug and Explain (8 min)
5. Get ready to use the broken code worksheet. You use the trace method to find 2 logic errors WITHOUT running the code. Write fixes on the worksheet. Then download and confirm the fix works.
6. Two you present their 3-decision system. They must use the logic flow diagram as a visual aid and say: 'The AND condition means both ___ AND ___ must be true. The OR condition means either ___ OR ___ is enough.'
7. Maths debrief: 'From your list of 10 numbers, how many satisfied BOTH conditions? How many satisfied at least ONE? What is the difference?' You calculate and share.
### WRAP-UP – Save and Collect (2 min)
8. Rename project 'T2W2_[Name]_Logic'. Disconnect Micro:bit and return to kit box.
9. Collect trace worksheets, logic flow diagrams, and broken code worksheets. Trace worksheet is this week's formal artifact — check all 3 prediction/actual rows are completed.

## Check your understanding
- Formative (During)
- Observation: Does the AND condition programme only show the sun when BOTH temperature > 25 AND Button A are true? (functionality check)
- Does the OR condition programme correctly respond to EITHER button press OR shake? (functionality check)
- Logic flow diagram completed with all decision diamonds and outcomes filled in before coding began? (design check)
- Truth table completed correctly for both AND and OR? (worksheet check)
- Exit Assessment
- You presents 2 verbal scenarios: ① 'Temperature is 22°C and Button A is pressed. What does your AND programme show?' ② 'The Micro:bit is NOT shaken and Button A is NOT pressed. What does your OR programme show?' Learner answers and explains why. 2 points for you — also record whether the trace worksheet predictions matched actual outputs.
- Differentiation
- Support: Provide a pre-built programme with the AND structure already in place; learner only selects the sensor values and icons. Replace the 4-row truth table with a 2-row version (T+T only, F+F only). Extension: Design a 4-decision system using AND, OR, and a nested condition together. Write a paragraph (min. 5 sentences) explaining all 4 outcomes in plain English as if writing instructions for a person who cannot see the code.
