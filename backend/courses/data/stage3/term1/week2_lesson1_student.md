# Week 2 - Lesson 1

## Session length
**About half of this week's plan** (you will finish in Lesson 2)

## Today you will learn
- Read a provided MakeCode programme (printed + on screen) and predict what it will do before running it
- Answer 5 code comprehension questions about the programme (input, output, sequence, value, effect)
- Download and run the programme to check predictions against actual behaviour
- Modify at least one value in the programme (e.g. change a number or delay) and explain the effect
- Convert a delay value between milliseconds and seconds
- Explain in one sentence why reading code carefully matters before making changes

## Big idea
Reading code is like reading instructions in a book. Before you change anything, you must understand what it already does.

## What you need
- 4 BBC Micro:bit v2 kits + USB cables
- 4 shared laptops with MakeCode open
- Printed 'Code Comprehension Worksheet' (A4 for you) – shows the MakeCode programme as a screenshot with 5 questions
- Printed MakeCode programme screenshot (colour, A4 for you)
- Sticky notes (for predictions – 3 for you)
- A computer or screen to follow along
- Vocabulary card set from Week 1 (reused) + new card: 'delay', 'iteration'
- 'One Star, One Wish' feedback cards

## Links to English and Maths
- **English:** Reading comprehension: you read the provided programme 'as a text'. Answer 5 structured questions: What does this programme do? What is the input? What is the output? What happens first? What could go wrong? You write answers in full sentences.
- **Maths:** Identify all numerical values in the code (delays in milliseconds). Unit conversion: 500ms = 0.5 seconds; 1000ms = 1 second. Challenge: 'If the delay is 2000ms, how long does the LED stay on?' Read and extract numbers from code blocks.

## Let's begin

### HOOK – Can You Read This? (10 min)
1. Show a projected MakeCode programme on screen (a simple programme: on button A pressed -> show number 7 -> pause 1000ms -> clear screen). Do NOT explain it. Ask: 'What do you think this does?'
2. You write their prediction on a sticky note. Collect predictions and read 2–3 aloud. Bridge: 'Let's find out if you're right!'
3. Vocabulary recap: hold up 'input', 'output', 'algorithm' cards from Week 1. You give a definition. Introduce new cards: 'delay' (how long to wait), 'iteration' (one complete run of a loop).
4. Ask: 'Why should we read code carefully BEFORE changing it?' Take 2–3 answers. Write on board: 'Read -> Predict -> Run -> Compare -> Modify.'
### DESIGN – Comprehension Questions (10 min)
5. Get ready to use printed Code Comprehension Worksheets and the programme screenshot. You read the programme silently for 2 minutes.
6. You answer the 5 comprehension questions together in writing. Check your work carefully – prompt: 'Find the INPUT block. What triggers it?'
7. You share answers with another pair (think-pair-share). You clarifies any misconceptions before running the code.
### DELIVER – Run, Compare, Modify (30 min)
8. Get ready to use Micro:bits and laptops. Driver opens MakeCode and recreates the provided programme from the worksheet. Navigator checks block by block against the printed sheet.

## Save your progress
Keep your MakeCode project and worksheets ready for Lesson 2, where you will finish this week's activities and check your learning.
