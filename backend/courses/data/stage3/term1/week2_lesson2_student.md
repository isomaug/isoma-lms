# Week 2 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Read a provided MakeCode programme (printed + on screen) and predict what it will do before running it
- Answer 5 code comprehension questions about the programme (input, output, sequence, value, effect)
- Download and run the programme to check predictions against actual behaviour
- Modify at least one value in the programme (e.g. change a number or delay) and explain the effect
- Convert a delay value between milliseconds and seconds
- Explain in one sentence why reading code carefully matters before making changes

## Continue

### DELIVER – Run, Compare, Modify (30 min)
1. Step 1 (8 min): Download and run the programme. You compare the actual behaviour to their sticky-note prediction. Were they right? Write 'Prediction: ___ / Actual: ___' on worksheet.
2. Step 2 (6 min): Code comprehension questions on screen – you ask each pair one question from the worksheet. You respond orally.
3. Step 3 (10 min): Modify task – change the delay from 1000ms to 500ms. Predict what will change. Download. Run. Confirm. Then change it to 2000ms. What changes now?
4. Step 4 (6 min): Continue with the next steps yourself. Modify the displayed number/icon to something different. Re-download and demonstrate to you.
### DISCOVER – Debug Challenge (8 min)
5. You puts a deliberately broken programme on the projected screen (e.g. missing a block, wrong event). Ask: 'What is wrong with this code? How would you fix it?'
6. You discuss and write their fix on a sticky note. Two you share their solution. You reveals the correct fix.
7. Debrief: 'Reading code is like reading instructions – you must understand before you change.' You says one thing they found in the code that surprised them.
### WRAP-UP – Save and Reflect (2 min)
8. Rename MakeCode project to 'Week2_[Name]'. Disconnect Micro:bit carefully. Collect worksheets.
9. Exit prompt: learner completes the sentence on the back of their worksheet: 'When I changed the delay, the programme became ___ because ___.'

## Check your understanding
- Formative (During)
- Observation: Did learner answer 4/5 comprehension questions correctly? (worksheet check)
- Can learner convert 500ms to seconds? (oral or written check)
- Modified programme runs with the intended change? (screen observation)
- Exit Assessment
- You holds up the programme screenshot. Learner points to: ① the INPUT block ② the OUTPUT block ③ one numerical value ④ and says what would happen if that number doubled. 4 points total – record for you.
- Differentiation
- Support: Pre-recreate the programme in MakeCode so learner only needs to run and observe before modifying. Provide a sentence frame for comprehension questions.
- Extension: Write a brand-new 3-block programme from scratch that uses a different input event (e.g. shake) and explain it to a partner as if teaching them.
