# Week 6 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Write a 3-scene story plan on paper using the narrative structure: Setting (Scene 1), Conflict/Problem (Scene 2), Resolution (Scene 3)
- Translate each scene into a specific LED animation sequence (icons, numbers, scrolling text) planned on a storyboard worksheet
- Code each scene as a button-triggered block in MakeCode: Button A -> Scene 1, Button B -> Scene 2, Button A+B -> Scene 3
- Download, run, and test the full animation, checking all 3 scenes display correctly in sequence
- Revise the code or story plan based on peer feedback (1 Star, 1 Wish format)
- Present the animated story to the group using the written plan as a script

## Continue

### DESIGN – Write the Story & Storyboard (15 min)
1. You checks: every pair must have a complete storyboard BEFORE opening MakeCode.
2. Ask: 'What is your Button A+B trigger?
3. Have you planned all 3 scenes?'
### DELIVER – Code, Test, and Revise (25 min)
4. Get ready to use Micro:bits and laptops.
5. Assign Driver and Navigator.
6. Navigator holds the storyboard – Driver codes from the storyboard exactly.
7. No improvising.
8. Scene 1 (7 min): Code 'on button A pressed' -> LED animation for Scene 1 (icons + scrolling text + pause). Download and test. Does it match the storyboard?
9. Scene 2 (7 min): Code 'on button B pressed' -> LED animation for Scene 2. Download and test. Navigator checks against storyboard timing.
10. Scene 3 (7 min): Code 'on button A+B pressed' -> LED animation for Scene 3. Download and test the FULL story: press A, then B, then A+B. Does the complete 3-scene story run correctly?
11. Revise (4 min): Continue with the next steps yourself. New Driver fixes any bugs or improves one scene based on the storyboard notes. Re-download and run.
### DISCOVER – Present and Peer Review (8 min)
12. Gallery performance: each pair presents their animated story to yourself. Presenter uses the written story plan as a script, reading one sentence per scene while the Micro:bit plays the animation.
13. Audience members complete a 'One Star, One Wish' card for each presentation. You collects and gives to the presenting pair.
14. Reflection: 'Why did we write the story on paper FIRST?' You respond. Guide to: the paper plan is the algorithm – you cannot code something you have not planned.
15. Maths check: Ask yourself 2 you: 'What fraction of your total story time is Scene 1?' You calculate and answer.
### WRAP-UP – Save and Collect (2 min)
16. Rename MakeCode project 'Week6_[Name]_Story'. Disconnect Micro:bit carefully.
17. Collect story plan worksheets and storyboard grids. Both are formally assessed this week. Note: written plan + revised plan + peer review card submitted.

## Check your understanding
- Formative (During)
- Observation: Does the 3-scene animation run through all scenes in the correct order? (functionality check)
- Is the written story plan complete with setting, conflict, and resolution? (worksheet check)
- Is the storyboard grid completed with LED plan, button trigger, and duration for each scene? (storyboard check)
- Did learner use partner feedback to revise their story plan? (peer review card check)
- Exit Assessment
- Ask yourself each presenter:
- ① 'What is the CONFLICT in your story?'
- ② 'Which button triggers Scene 3?'
- ③ 'What is the total duration of your animation?' Learner answers from their storyboard.
- 3 points for you – recorded on assessment sheet.
- Differentiation
- Support: Provide a pre-written story plan with blanks to fill in. Pre-build the button trigger blocks in MakeCode so learner only adds the LED animation content inside each block. Extension: Add a fourth scene triggered by the shake event. Add a scrolling title screen before Scene 1. Record the total timing, calculate what percentage of the story is each scene, and present the percentages as a pie chart sketch.
