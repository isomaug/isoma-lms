# Week 7 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Read the improvement goal card from Week 22 and write a one-sentence design intention stating how the Final Sprint project will address it
- Complete a 6-section design brief: Title, Problem Statement, Who It Is For, How It Works (with pseudocode including at least one function call), What I Used (inputs, outputs, variables, conditions, Term Three skill used), Mathematical Element (calculation or graph)
- Build a working Micro:bit prototype that demonstrably uses all of: a named variable, at least one if/else condition, a sensor input, a self-created function, and either an accelerometer reading OR a Bluetooth service OR a classifier structure
- Run 3 planned test cases from a pre-written test log (input -> expected output -> actual output -> pass/fail); fix all failing test cases before saving the final version
- Complete a 3-item self-evaluation: one strength from the test log results, one bug fixed during the session, one specific improvement that could be made with more time
- Rehearse the Demo Day 6-section presentation structure using the design brief as a script — timed at exactly 3 minutes with a partner

### DELIVER – Build, Test, and Iterate (27 min)
1. Build Phase 1 (12 min): establish the core mechanic — variable, sensor input, condition. Include the function definition and at least one call point. Download and run Test Case 1. Record Actual Output. Pass or Fail? If Fail — write the bug type and fix on the test log immediately, do not defer.
2. Build Phase 2 (10 min): add the Term Three skill element — the feature that makes this project distinct from a Term One or Term Two project. Add sound or narrative if time allows. Continue with the next steps yourself. New Driver runs Test Case 2, records result, and makes at least one refinement identified by the Navigator.
3. Test Case 3 and final fixes (5 min): run Test Case 3. Record. Address any remaining fails. Check: does the programme currently meet ≥2/4 on EVERY DDD Part 8.5 criterion? If any criterion is still at 1 — fix it now. Update the pseudocode in Section 4 if the code changed during build.
### DISCOVER – Rehearse and Self-Evaluate (8 min)
4. You completes the self-evaluation frame independently: Strength (citing test log evidence), Bug Fixed (naming type and fix), Improvement With More Time (technically specific). Check your work carefully: 'If your strength just says "it worked", that is not specific enough. Cite your test log — which test case passed, and what did it prove about your programme?'
5. Timed rehearsal: you take turns presenting to each other for exactly 3 minutes using the Demo Day structure card. Partner times with a phone or watch. After each rehearsal, partner says: 'You used ___ seconds too many / too few. The section that needs more time is ___.' Learner adjusts timing notes on the structure card.
6. You previews Demo Day: 'Next week, you present this project to the group. Your design brief is your script. Your test log is your evidence. Your self-evaluation is your reflection. Bring all three. Practice your 3 minutes at home this week.'

## Check your understanding
- Formative (During)
- You approval gate: all 6 brief sections and 3 test cases completed before coding — you signed? (design gate check)
- Prototype uses a named variable, an if/else condition, a sensor input, a self-created function, AND one Term Three skill? (5-point ILO + T3 skill check)
- All 3 test cases run, recorded with pass/fail, and failing cases fixed before saving? (test log integrity check)
- 3-minute rehearsal completed and timing feedback noted on presentation card? (Demo Day preparation check)
- Exit Assessment
- Ask yourself you: ① 'Which Term Three skill does your graduation project use — and where in the code is it?' ② 'Which test case was the hardest to pass — what was the bug and how did you fix it?' ③ 'What is your mathematical element and what does it prove about your project?' 3 points for you. Flag any learner with a failing test case still unresolved — they must be offered targeted support before Demo Day. Record all scores on the cumulative assessment record per DDD Part 10.3.
- Differentiation
- Support: Reduce to 4 brief sections (skip Section 3 and Section 6). Reduce to 2 test cases. Allow learner to build upon and extend an existing project from a prior term rather than starting from scratch — the Term Three skill must be added as a new feature. Provide a partially built MakeCode template with the function structure already in place. Extension: Build two distinct projects — one that uses the accelerometer for data collection (ILO 2.3) and one that uses AI classification logic (ILO 2.2). Write a one-paragraph comparison of both projects explaining which better demonstrates Stage 3 mastery and why — evaluative writing at Bloom's L5.
