# Week 2 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- State and explain the 5-step debugging protocol: Read -> Predict -> Run -> Compare -> Fix — one sentence per step
- Apply the protocol to Bug Set A: a provided programme with 2 logic errors — locate and fix both without running the code first (trace debugging)
- Apply the protocol to Bug Set B: a provided programme with 2 syntax/structural errors — locate and fix both by reading the code and running it once to confirm
- Apply the protocol to Bug Set C: a complex programme with 3 errors spanning ILO 2.1 (wrong event block) and ILO 2.2 (inverted condition) — locate and fix all 3
- Document every bug found across all three bug sets in a structured debugging log: Bug number / Location / Type / What it caused / Fix applied
- Write a 3-sentence reflection: what strategy helped most, what was hardest to find, and one rule they will follow in their own coding to prevent that type of bug

## Check your understanding
- Formative (During)
- Bug Set A: both errors identified by trace (without running the code first) and fixes verified on Micro:bit? (trace debugging check)
- Bug Set B: both structural errors located after a single run and fixes verified? (run-and-compare debugging check)
- Bug Set C: all 3 errors found independently without you hints, fixes verified, and all rows in debugging log complete? (independent debugging check — hardest gate)
- Debugging log: all 7 rows completed with specific error type, effect, fix, and verified Y/N? (artifact quality check)
- Exit Assessment
- Read one line of JavaScript from Bug Set C aloud and asks you: ① 'What error type is this — logic or syntax?' ② 'What is the root cause of this error?' ③ 'What is your prevention rule for this type of error?' 3 points for you. You records on assessment log. Also note whether the learner's debugging log shows the full 5-step protocol was followed for Bug Set C (evidenced by the Predict and Compare entries).
- Differentiation
- Support: Reduce to Bug Sets A and B only — skip Bug Set C. Provide Bug Set A with errors pre-highlighted in yellow (you still need to identify what is wrong and fix it). Allow 2 runs of Bug Set B before requiring the fix to be written. Extension: Write a fourth bug set of their own — create a MakeCode programme that contains exactly 2 logic errors and 1 syntax error, without telling a partner where the bugs are. Swap with a partner and time how long it takes each person to find all 3 bugs. Compare strategies.
