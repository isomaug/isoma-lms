# Week 8 - Lesson 1

## Session length
**About half of this week's plan** (you will finish in Lesson 2)

## Today you will learn
- Deliver a 90-second structured presentation explaining the game's state design, algorithm, and one iteration improvement made based on playtesting
- Demonstrate the game running live through at least one complete state cycle (Title -> Playing -> Win)
- Answer one technical question from a guest using subject-specific vocabulary from both Term 1 and Term 2
- Complete a Term 2 retrospective reflection identifying the most important computational thinking skill developed and setting a specific, measurable goal for Stage 3

## Big idea
You have gone through the complete software development lifecycle this term: design -> specify -> build -> test -> iterate -> present. This is exactly what professional game developers do. Today you show what that process produces.

## What you need
- 4 tablets with Stack KIDI — PLAYTESTED GAME files from Lesson 15

## Links to English and Maths
- **English:** The 90-second presentation requires the highest level of oral English this term: technical vocabulary, logical structure, narrative (the story of the development journey), and argument (why the design decisions were correct). This mirrors the structure of a professional product pitch. Vocabulary used in the presentation must include at least 5 of: algorithm, state, transition, decompose, variable, iterate, playtest, specify, debug, iterate.
- **Maths:** Quantitative reporting in the presentation: you must cite at least two numbers — e.g. "My game has 3 states and 4 sub-problems. After playtesting, 2 of 3 testers experienced the same issue — a 67% frequency. Our fix reduced that to 1 in 3 testers — 33%." This is evidence-based evaluation, the same skill used in data science.

## Let's begin

### PREPARATION — Final Rehearsal and Setup (12 min)
1. Presentation Structure Card (A5 for you): 90-second script framework — ① Game title and concept (15s) ② Run the game live: Title -> Playing -> Win (30s) ③ Explain the state design: "My game has ___ states. The transition from PLAYING to WIN is triggered by ___." (20s) ④ Describe one playtest improvement: "Before playtesting, ___. A tester showed us ___. We fixed it by ___." (15s) ⑤ Vocabulary highlight: "The most important computing concept in my game is ___ because ___." (10s)
2. Demo Day Rubric (A4 for you, scored by you): 6 criteria — Game Runs Complete State Cycle / States Explained / Algorithm Described / Playtest Improvement Named / Vocabulary (5+ terms) / Confidence and Clarity — each scored 0–3 (max 18)
3. Guest Technical Question Bank (A5, for you use): 8 prepared questions at increasing difficulty — you selects based on the pair's presentation level
4. Term 2 Skills Passport (A5 for you): 10 stamps — Algorithm, Bug, Loop, Multi-character, Messages, Variables, Wait, Decomposition, Game Design, Playtesting
5. Stage 2 Term 2 Certificate (A5, pre-printed, 1 for you)
6. Guest Observation Cards (A5, 2 per guest): structured observation with prompts — "The computing concept I noticed was ___. One question I have for the designer: ___. One word to describe this programmer: ___."

### DELIVER — The Algorithm Game Expo (30 min)
7. Final game test: you runs each game once. Check: Title Screen -> Playing -> Win cycle works. Any broken game — load the pre-tested Lesson 14 backup.
8. Station setup: tablet, specification document, state transition diagram, playtest materials displayed at each station — guests will be able to read the full design process.
9. Rehearsal Round 1 (3 min): each pair rehearses 90 seconds alone using the Presentation Structure Card.
10. Rehearsal Round 2 (3 min): each pair presents to adjacent pair. Adjacent pair gives one piece of feedback using only vocabulary from the Guest Technical Question Bank.
11. Vocabulary final check: you reads 5 vocabulary words — you must use each word in a sentence about their game (not a definition). Speed round: 30 seconds.
12. Welcome guests. You addresses guests: "Today these you will not just show you a game — they will explain the algorithm behind it, the states it moves through, and how they improved it based on real user testing. Please ask questions and play their games."
