# Week 3 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Apply decomposition to break a complex programme brief into at least 4 named sub-problems
- Build each sub-problem independently and test it before connecting it to the next
- Combine variables, Wait blocks, loops, messages, and size/speed effects in a single coherent programme
- Describe the role of each sub-problem in the overall programme using precise computing vocabulary

## Continue

### DELIVER — Build Sub-Problem by Sub-Problem (30 min)
1. Build only Sub-problem 1 first (7 min). When complete, run ONLY that portion. Does it pass its test condition? Tick the test checklist. Only then proceed to Sub-problem 2.
2. Build Sub-problem 2 (7 min). Test. Tick. Proceed.
3. Connect Sub-problem 1 + 2 (3 min): run both together. Does the combination work as intended? Fix any integration issue now.
4. Build Sub-problem 3 (6 min). Test. Tick. Connect to 1+2. Run all three.
5. Build Sub-problem 4 (5 min). Test. Tick. Connect all four. Run full programme.

### DISCOVER — Decomposition Debrief (7 min)
6. Bug at any stage? Debugger process applies: identify which sub-problem contains the bug (it is ALWAYS in the most recently added component — unless a previous test was skipped).
7. You checkpoint at 20 min: "How many sub-problems have been tested and ticked?"
8. You report: how many sub-problems were fully completed? (0–4.) What blocked completion?
9. Think about: "Was it easier to debug when you built sub-problem by sub-problem? Why?"
10. Key insight: "A bug found when building sub-problem 3 is almost always IN sub-problem 3 — because sub-problems 1 and 2 were already tested. This is why we test each part before adding the next."

### WRAP-UP (3 min)
11. You annotate their decomposition sheet: circle the sub-problem that was most challenging. Write one word: why.
12. Save projects. Complete the test checklist.
13. Collect decomposition sheets for portfolios.
14. Preview: "Next lesson — Term 2 Week 4 project sprint. This time, you write your own brief AND decomposition plan. Completely independent."

## Check your understanding
- Formative (During)
- Decomposition planning sheet approved: 4 sub-problems with test conditions written
- Sub-problem test checklist: number of ticks recorded at end of session
- You checkpoint at 20 min build: sub-problem progress noted
- Debugging location correctly identified as "most recently added sub-problem"
- Exit / Summative
- "If you find a bug when adding Sub-problem 3, where do you look first — and why?" Learner should say: Sub-problem 3, because Sub-problems 1 and 2 were already tested and passed. Correct reasoning = full mark.
- Differentiation
- Support: Reduce to 3 sub-problems; you pre-builds Sub-problem 1 and learner builds 2 and 3. Extension: After completing all 4 sub-problems, write a 1-page "programme specification" — a formal description of what the programme does, what each sub-problem achieves, and what inputs and outputs exist.
