# Week 3 - Lesson 1

## Session length
**About half of this week's plan** (you will finish in Lesson 2)

## Today you will learn
- Apply decomposition to break a complex programme brief into at least 4 named sub-problems
- Build each sub-problem independently and test it before connecting it to the next
- Combine variables, Wait blocks, loops, messages, and size/speed effects in a single coherent programme
- Describe the role of each sub-problem in the overall programme using precise computing vocabulary

## Big idea
Complex problems are just lots of simple problems linked together. Break the big problem into small pieces, solve each piece, then connect them. This is DECOMPOSITION — the most powerful thinking skill in computing.

## What you need
- 4 tablets with Stack KIDI — existing projects

## Links to English and Maths
- **English:** Decomposition as a writing strategy: "Before writing a long essay, you break it into: introduction, 3 paragraphs, conclusion. This is decomposition." You write a paragraph plan BEFORE the essay — same as the sub-problem plan before the programme. Vocabulary: decompose, sub-problem, component, systematic, integrate, connect, whole, part.
- **Maths:** Problem structure: "The full programme = Sub-problem 1 + Sub-problem 2 + Sub-problem 3 + Sub-problem 4. If Sub-problem 1 has 4 blocks and Sub-problem 2 has 3 blocks, how many blocks minimum does the full programme have so far? (7.) What is the minimum for 4 sub-problems if each has at least 2 blocks?" (8.) Estimate and then count the actual total.

## Let's begin

### HOOK — The Building Site Analogy (8 min)
1. Decomposition planning sheet (A4 for you): large outer box = "The Full Programme". Inside: 4 smaller boxes = Sub-problem 1, 2, 3, 4. Each sub-problem box has: Goal / Blocks needed / Test condition
2. Complex programme brief cards (4 different briefs, one for you): each describes a 2-character, 2-page interactive programme using all 4 skill types from Term 2
3. Sub-problem test checklist (A5): tick each sub-problem as it passes its test condition before moving to the next
4. Block skill reference poster (A3): all skill types from Term 1 + Term 2 — Movement / Appearance / Control / Sound / Trigger / Messages / Variables / Wait
5. Show an image (or describe): "A house has 4 teams working on it — the foundation team, the walls team, the roof team, and the finishing team. Can the roof team start before the walls are done?"
6. Bridge: "Building a complex programme is exactly the same. Today we have 4 sub-problems — like 4 teams. We build and TEST each one before connecting them."
7. Show the decomposition planning sheet. Walk through what each box means.

### DESIGN — Decomposition Planning (12 min)
8. Introduce the brief cards. Read one aloud. Ask: "What are the 4 natural parts of this programme?"
9. Get ready to use brief cards and decomposition planning sheets.
10. Step 1 (4 min): Read the brief. Identify the 4 natural sub-problems and write each in a box.
11. Step 2 (4 min): For each sub-problem, write: which blocks are needed? What is the test condition (how will you know this sub-problem is working correctly)?
12. Step 3 (4 min): Write the order of building — which sub-problem MUST be built first? (Usually: triggers and basic character setup first, then effects, then coordination.)
13. You approves decomposition plan: "Can I see 4 clear, testable sub-problems?" Tick and proceed.
