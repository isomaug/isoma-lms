# Lesson 16  ·  Term 2 · Week 8  ★  DEMO DAY ★

**Duration:** 60 minutes (split across Week 8 Lesson 1 start + Lesson 2 finish)
**Term / Week:** Term 2 · Week 8
**Age Range:** 7–8 years
**Hardware:** Tablets with Stack KIDI App
**Bloom's:** L4 Analyse · L5 Evaluate · L6 Create

**Big Idea:** You have gone through the complete software development lifecycle this term: design → specify → build → test → iterate → present. This is exactly what professional game developers do. Today you show what that process produces.

**Source plan:** `Stage2_Lesson16_Term2_Week8.docx`

## Learning Objectives

- Deliver a 90-second structured presentation explaining the game's state design, algorithm, and one iteration improvement made based on playtesting
- Demonstrate the game running live through at least one complete state cycle (Title → Playing → Win)
- Answer one technical question from a guest using subject-specific vocabulary from both Term 1 and Term 2
- Complete a Term 2 retrospective reflection identifying the most important computational thinking skill developed and setting a specific, measurable goal for Stage 3

## Materials and Preparation

- 4 tablets with Stack KIDI — PLAYTESTED GAME files from Lesson 15

## Cross-Curricular Links

**English:** The 90-second presentation requires the highest level of oral English this term: technical vocabulary, logical structure, narrative (the story of the development journey), and argument (why the design decisions were correct). This mirrors the structure of a professional product pitch. Vocabulary used in the presentation must include at least 5 of: algorithm, state, transition, decompose, variable, iterate, playtest, specify, debug, iterate.

**Maths:** Quantitative reporting in the presentation: pairs must cite at least two numbers — e.g. "My game has 3 states and 4 sub-problems. After playtesting, 2 of 3 testers experienced the same issue — a 67% frequency. Our fix reduced that to 1 in 3 testers — 33%." This is evidence-based evaluation, the same skill used in data science.

## Lesson Structure

### PREPARATION — Final Rehearsal and Setup (12 min)
1. Presentation Structure Card (A5 per pair): 90-second script framework — ① Game title and concept (15s) ② Run the game live: Title → Playing → Win (30s) ③ Explain the state design: "My game has ___ states. The transition from PLAYING to WIN is triggered by ___." (20s) ④ Describe one playtest improvement: "Before playtesting, ___. A tester showed us ___. We fixed it by ___." (15s) ⑤ Vocabulary highlight: "The most important computing concept in my game is ___ because ___." (10s)
2. Demo Day Rubric (A4 per pair, scored by facilitator): 6 criteria — Game Runs Complete State Cycle / States Explained / Algorithm Described / Playtest Improvement Named / Vocabulary (5+ terms) / Confidence and Clarity — each scored 0–3 (max 18)
3. Guest Technical Question Bank (A5, for facilitator use): 8 prepared questions at increasing difficulty — facilitator selects based on the pair's presentation level
4. Term 2 Skills Passport (A5 per learner): 10 stamps — Algorithm, Bug, Loop, Multi-character, Messages, Variables, Wait, Decomposition, Game Design, Playtesting
5. Stage 2 Term 2 Certificate (A5, pre-printed, 1 per learner)
6. Guest Observation Cards (A5, 2 per guest): structured observation with prompts — "The computing concept I noticed was ___. One question I have for the designer: ___. One word to describe this programmer: ___."
7. Final game test: facilitator runs each game once. Check: Title Screen → Playing → Win cycle works. Any broken game — load the pre-tested Lesson 14 backup.

### DELIVER — The Algorithm Game Expo (30 min)
8. Station setup: tablet, specification document, state transition diagram, playtest materials displayed at each station — guests will be able to read the full design process.
9. Rehearsal Round 1 (3 min): each pair rehearses 90 seconds alone using the Presentation Structure Card.
10. Rehearsal Round 2 (3 min): each pair presents to adjacent pair. Adjacent pair gives one piece of feedback using only vocabulary from the Guest Technical Question Bank.
11. Vocabulary final check: facilitator reads 5 vocabulary words — each learner must use each word in a sentence about their game (not a definition). Speed round: 30 seconds.
12. Welcome guests. Facilitator addresses guests: "Today these learners will not just show you a game — they will explain the algorithm behind it, the states it moves through, and how they improved it based on real user testing. Please ask questions and play their games."
13. Expo open: guests circulate to all 4 stations. At each station, pair presents 90-second explanation then hands the game to the guest to play.

### DISCOVER — Retrospective and Awards (14 min)
14. After guest plays: pair points out one specific part of the game: "That transition you just experienced — that is a state change from PLAYING to WIN. It was triggered by ___."
15. Facilitator selects one Technical Question Bank question per pair and asks it during their presentation. Records the answer quality on the rubric.
16. Guest Observation Cards filled in during and after play at each station.
17. Guests seated. Facilitator leads a 3-minute debrief: "What surprised you most about how these games were made?" Two guests share responses.
18. Skills Passport completion: facilitator reads each of the 10 Term 2 skills. Learners stamp/tick each one demonstrated today or across the term.
19. Term 2 Retrospective Reflection (individual, 3 min): "The most important computational thinking skill I developed this term: ___. Evidence: ___. My specific goal for Stage 3: ___." Goals must be specific and measurable — not "to get better" but "to build a game with 4 states independently."

### WRAP-UP (4 min)
20. Certificate presentation: each learner called by name. Presented with Stage 2 Term 2 Certificate. Facilitator reads one specific achievement from the rubric for each learner.
21. Closing: class stands. Each learner says one word that describes what they made this term. Facilitator records all words on the board — a collective portrait of the term.
22. Collect all materials for portfolios: specification, state diagrams, playtest records, rubrics, passports, reflection cards.
23. Save final games as "FINAL GAME — [Pair Names] — Term 2 Demo Day."
24. Return tablets. Thank guests.
25. Facilitator post-session: review all rubric scores and retrospective goals. Any learner below 10/18 — prepare a specific support note for Stage 3 Term 1 Week 1.

## Assessment

- Formative (During)
- Demo Day Rubric: 6 criteria × 3 = 18 max. Minimum 12/18 for Stage 3 readiness recommendation
- Technical question answered using correct vocabulary (facilitator tally of terms used)
- Game demonstrates complete state cycle live in front of guests (all 3 states observed)
- Skills Passport: minimum 8/10 stamps for full Term 2 completion
- Exit / Summative
- Term 2 Retrospective Reflection. Facilitator reviews: is the cited skill supported by rubric evidence? Is the Stage 3 goal specific and measurable? Any goal that is vague is returned for revision before filing. The goal becomes the first talking point in Stage 3 Week 1.
- Differentiation
- Support: Learner presents only the game demo (live run) without the full structure card explanation. Facilitator provides verbal scaffolding for the vocabulary question. Extension: Learner prepares and delivers a 45-second "opening address" to all guests before the Expo begins — explaining what an algorithm is, what a game state is, and why playtesting matters. This is an advanced public speaking task.
