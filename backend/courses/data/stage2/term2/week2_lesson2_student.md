# Week 2 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Locate the Wait block in Stack KIDI and explain its purpose: to pause the current character's programme for a set number of seconds
- Build a sequence where a Wait block creates a meaningful dramatic pause before an action
- Coordinate two characters performing one after the other using ONLY Wait blocks (no message blocks)
- Compare Wait-block coordination with Message-block coordination and explain one advantage of each

## Continue

### DELIVER — Build Timed Choreography (28 min)
1. You approves: "Is the Wait value specific? Is there a timeline showing both characters?" Tick and proceed.
2. Open the existing 2-character Stack KIDI project from Term 1.
3. Step 1 — Measure Character 1 (5 min): Run Character 1's programme with a stopwatch. Record exact running time in seconds. Convert to Wait units (× 10). Note on design sheet.
4. Step 2 — Add Wait to Character 2 (8 min): At the START of Character 2's programme row, add a Green Flag trigger (if not already present), followed immediately by a Wait block set to the calculated value. Run both characters simultaneously — does Character 2 start at the right moment?
5. Step 3 — Fine-tune timing (8 min): Adjust the Wait value until the transition looks natural. Try Wait value −2, exact value, and +2. Record which looks best and why.

### DISCOVER — Choreography Performance (10 min)
6. Step 4 — Compare methods (7 min): Open the comparison table. Recall the Message block approach from Term 1. Fill in: "Wait blocks — Advantage: ___. Disadvantage: ___. Message blocks — Advantage: ___. Disadvantage: ___."
7. Each pair performs their choreographed 2-character story to the adjacent pair.
8. Audience watches and answers: "Did the timing feel natural? When did Character 2 start — too early, just right, or too late?"
9. Performers adjust based on feedback if needed (one change only, 2 minutes maximum).

### WRAP-UP (4 min)
10. Think about: "When is it better to use Wait blocks instead of Message blocks?" (Answer: when you know exactly how long something takes. Message blocks are better when you don't know — or when timing might vary.)
11. You completes: "Wait blocks are useful when ___. Message blocks are better when ___."
12. Save choreography projects. Collect design sheets.
13. Preview: "Next lesson — we combine Wait blocks, Size, Speed, and Variables to build the most complex programme so far this term!"

## Check your understanding
- Formative (During)
- Choreography design sheet approved: timeline drawn, Wait value calculated
- Wait block value measured, calculated, and adjusted (3 values tested)
- Comparison table completed (Wait vs Message advantages and disadvantages)
- Audience timing feedback received and adjustment made (if needed)
- Exit / Summative
- "What is the difference between a Wait block and a Message block?" Learner must reference: timing certainty — Wait requires you to know how long; Message fires automatically when the condition is met. Both concepts correct = full mark.
- Differentiation
- Support: You pre-calculates the Wait value; learner only needs to find the Wait block and set the number. Extension: Build a 3-character choreography where Character 3 waits for BOTH Character 1 AND Character 2 to finish before starting — calculate the total wait time for Character 3.

## Stay safe
Safeguarding Note: Timing discussions: avoid references to waiting in contexts that could be anxiety-inducing (e.g. waiting for test results, medical waits). Keep all Wait block examples in a positive, creative, story-based context.
