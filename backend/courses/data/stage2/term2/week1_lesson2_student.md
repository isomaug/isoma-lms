# Week 1 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Define a variable as "a named store for a value that can change over time" using an everyday analogy
- Use Stack KIDI's number display block to show an on-screen number that the learner can interact with
- Build a tap-triggered counter that increments a visible number each time the character is tapped
- Predict the final displayed number after a specific sequence of increment and decrement actions

## Continue

### DELIVER - Build the Score Counter (28 min)
1. You approves each design. Check: is the starting value defined? Is the increment trigger clear? Does the name describe what is being counted?
2. Open Stack KIDI. New project. Add character.
3. Step 1 - Reset programme (5 min): Green Flag row -> Add a Number Display block showing 0. This is the "reset to zero" programme. Run with Green Flag. Confirm number shows 0 on screen.
4. Step 2 - Tap to increment (10 min): Add an On-Tap trigger row. After the trigger, add a Number Display + 1 block (or equivalent increment block). Tap the character 5 times. Observe: does the number increase by 1 each tap? Record the number after each tap in a tally.
5. Step 3 - Test the prediction challenge (8 min): Get ready to use prediction challenge cards. Without running the programme, you predict the final number after the described sequence of taps. Write prediction. Then run the sequence and compare. Were they right?

### DISCOVER - Variable Showcase and Maths Link (10 min)
6. Step 4 - Decrement (5 min): Add a second character or a second tap row that DECREMENTs (−1). Test: tap Character 1 three times (+3), then tap Character 2 once (−1). Predict: what is the final score? (Answer: 2.) Run and confirm.
7. Each pair demonstrates their counter to the adjacent pair: press Green Flag (resets to 0), then tap 5 times, then reset again.
8. Maths connection: "Tapping 5 times is like adding 1 five times: 0+1+1+1+1+1 = 5. What multiplication does that represent?" (5 × 1 = 5.)
9. Challenge: "Can you make the counter count by 2s instead of 1s?" One pair attempts by changing the increment value. Share the result.

### WRAP-UP (4 min)
10. Class reflection: "A variable stores a value that ___. Its name ___ but its value ___."
11. You writes: "A variable is ___. My variable today was called ___ and started at ___."
12. Save counter projects. Collect design sheets.
13. Preview: "Next lesson - we add a WAIT block to create timed pauses and build programmes that coordinate between time and events."

## Check your understanding
- Formative (During)
- Variable design sheet approved (name, starting value, trigger, target defined)
- Tally of 5 taps recorded with number after each (evidence of incrementing)
- Prediction challenge card: predicted and actual values recorded and compared
- Decrement tested and final value calculated and confirmed
- Exit / Summative
- Learner completes: "A variable is ___. My variable today was called ___ and started at ___." Check for: name + value + the idea that value changes. Full marks = all three concepts included.
- Differentiation
- Support: You pre-builds the Green Flag reset programme; learner builds only the On-Tap increment row. Extension: Build a programme where the character's SIZE changes in proportion to the score - as the score goes up, the character grows. This requires combining variables and appearance blocks.

## Stay safe
Safeguarding Note: Counting exercises in this lesson are abstract and fictional. Ensure counter themes do not reference competitive scoring between you in a way that could cause distress.
