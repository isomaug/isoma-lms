# Lesson 7

**Duration:** 60 minutes (split across Week 7 Lesson 1 start + Lesson 2 finish)
**Term / Week:** Term 1 · Week 7
**Age Range:** 7–8 years
**Hardware:** Tablets with Stack KIDI App
**Bloom's:** L3 Apply · L4 Analyse · L5 Evaluate · L6 Create

**Big Idea:** A real project uses ALL the skills together. Planning before coding always produces a better result than coding without a plan - even when you only have 60 minutes.

**Source plan:** `Stage2_Lesson7_Week7.docx`

## Learning Objectives

- Plan a complete 2-page, 2-character interactive story using a project brief template before writing any code
- Apply at least four different types of block from Term 1: movement, sound, loop, message, trigger
- Use the 3-step debugging process independently to identify and fix at least one bug encountered during the build
- Evaluate the completed project against a 4-criterion success checklist and give it a self-assessed score

## Materials and Preparation

- 4 tablets with Stack KIDI (clean new projects for each pair)

## Cross-Curricular Links

**English:** Project brief as a formal planning document - learners experience the discipline of planning completely before acting. Narrative writing: story must have a clear beginning (Page 1) and resolution (Page 2). Presentation vocabulary: "My project uses ___ because ___." Evaluation: "I am most proud of ___ in my project. If I had more time I would ___."

**Maths:** Project management: time allocation - 15 min design, 35 min build, 10 min evaluate. Learners self-manage against a visible countdown timer. Success criteria scoring: add up self-assessment scores (max 8). Calculate percentage: score ÷ 8 × 100 = ___%. Compare to previous lesson scores.

## Lesson Structure

### DESIGN SPRINT - Project Brief (15 min)
1. Project Brief Template (A4 per pair) - sections: Story Title | Characters (2) | Page 1 plan | Page 2 plan | Block types to use (checklist) | Success Criteria (4 items)
2. Project planning storyboard (A3, 4 frames) - 2 frames for Page 1, 2 frames for Page 2
3. Block type checklist sticker sheet - small stickers: movement, sound, loop, message, trigger, background. Pairs stick them onto the brief as they use each type
4. Success Criteria checklist (A5 per pair): ① 2 pages with different backgrounds ② 2 characters with different programmes ③ At least 1 loop used ④ Characters communicate using a message
5. Self-assessment scoring card: 0 = not yet | 1 = partially | 2 = fully achieved, for each of 4 criteria (max 8 points)
6. Distribute Project Brief Templates and storyboards. Timer starts: 15 minutes to complete all planning.

### DELIVER SPRINT - Build (35 min)
7. Step 1 (4 min): Story title + 2 characters named, coloured, and described in one sentence each.
8. Step 2 (5 min): Page 1 plan - background, what Character 1 does, what Character 2 does, what message is sent at the end.
9. Step 3 (4 min): Page 2 plan - new background, what happens after the message arrives.
10. Step 4 (2 min): Tick the block type checklist - which 4+ types will be used? Facilitator reviews each brief and approves. No pair moves to a device until the brief is approved.
11. Reminder: "The brief is your ALGORITHM. If you change something while coding, update the brief too."
12. Timer: 35 minutes. Pairs open new Stack KIDI projects.

### DISCOVER - Self-Evaluation (6 min)
13. Build in order: ① Set Page 1 background. ② Add and name Character 1. ③ Build Character 1's sequence (include a loop). ④ Add Send Message at end of Character 1. ⑤ Add and name Character 2 on Page 1. ⑥ Build Character 2's sequence with Receive Message trigger. ⑦ Add Page 2. ⑧ Set Page 2 background. ⑨ Build a short arrival sequence on Page 2.
14. Facilitator checkpoint at 15 minutes: "Has every pair got at least Page 1 built and running?" Pairs not at this point receive facilitator assistance.
15. Bug encountered? Use 3-step process: Identify (what is wrong?) → Locate (which block?) → Fix (change one thing at a time). Record any bugs fixed on the back of the project brief.
16. Stick block type stickers onto the brief as each block type is successfully used.
17. Timer alarm at 35 minutes: coding stops regardless of completion. Pairs run the current state and note what is complete and what is missing.
18. Distribute Self-Assessment Scoring Cards. Each pair scores their project on all 4 criteria.

### WRAP-UP (4 min)
19. Calculate total: ___ / 8. Calculate percentage.
20. Write: "I am most proud of ___ because ___. If I had more time, I would add ___."
21. Pair presents score and "most proud of" statement to the adjacent pair. Adjacent pair gives one "One Star, One Wish."
22. Save projects. Collect project briefs and scoring cards for portfolio folders.
23. Facilitator records scores per pair - these feed into the Term 1 Demo Day rubric.
24. Preview: "Next lesson - DEMO DAY! We present to guests. Practise your explanation tonight using the sentence starters on your project brief."

## Assessment

- Formative (During)
- Project brief approved before any coding begins (facilitator sign-off)
- Facilitator checkpoint at 15 min build mark: Page 1 running
- Block type sticker sheet: minimum 4 sticker types applied
- Bug recorded and fixed on back of brief (debugging process used)
- Self-assessment score: target 6/8 minimum for Demo Day readiness
- Exit / Summative
- Self-assessment scoring card completed. Facilitator reviews: is the self-assessment accurate? If a learner scored 8/8 but the project is incomplete, have a 1-minute conversation about honest self-evaluation.
- Differentiation
- Support: Simplify brief - only 1 page, 1 character, 3 block types. Facilitator assists with message setup. Extension: Add a third page showing an "ending" scene, and add a third character who only appears on Page 3 as a reward for completing the journey.
