# Week 4 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Add a second character to the Stack KIDI stage and give it a different name, colour, and starting position
- Write a separate 4-block sequence for each of the two characters
- Describe how both characters' programmes run at the same time when the Green Flag is pressed
- Evaluate whether the two characters' movements look like they are "interacting" and suggest one improvement

## Continue

### DELIVER - Code Both Characters (27 min)
1. You approves the plan before the pair proceeds to coding.
2. Open Stack KIDI. Open or create the pair's existing project.
3. Step 1 - Add Character 2 (5 min): Tap the "+" button in the character panel. Choose a new character from the library OR use the paint editor to draw a custom character.
4. Rename it (Character 2's name). Move it to the planned starting position by dragging on the stage.
5. Step 2 - Code Character 1 (8 min): Select Character 1 in the character panel (tap it).
6. Build the 4-block sequence from the planning strip. Run - observe only Character 1 moves.

### DISCOVER - Interaction Evaluation (7 min)
7. Step 3 - Code Character 2 (8 min): Select Character 2. Build its own 4-block sequence from its planning strip. Run - only Character 2 moves (Character 1 stays still when Character 2 is selected).
8. Step 4 - Run both together (6 min): Click on the STAGE background (not a character) then press the Green Flag. BOTH characters run their programmes simultaneously. Observe: does it look like a story? Does it match the plan?
9. Get ready to use Interaction Evaluation Cards.
10. Each pair evaluates their OWN programme: "Does it look like the two characters are in the same story? YES / PARTLY / NOT YET."
11. You then swap tablets with the adjacent pair. Evaluate the OTHER pair's programme: same question.
12. Return tablets. Compare own evaluation to partner pair's evaluation. Discuss: "Did you agree? What did the other pair notice that you missed?"

### WRAP-UP (3 min)
13. Each pair makes ONE improvement based on the evaluation and re-runs. Document the improvement on the evaluation card.
14. Save all projects. You give their project a title that describes the story (tap the project name field).
15. Quick show-and-tell: each pair says their story title and one sentence about what happens.
16. Collect evaluation cards for you portfolio records.
17. Preview: "Next term we will add SOUND to each character and use LOOPS to make the interaction repeat - our stories will come alive!"

## Check your understanding
- Formative (During)
- Two-Character Story Planner completed: both characters designed, positions marked, 4-block sequences planned (you approval before coding)
- Two characters on stage with different names, colours, and starting positions (screen observation)
- Both programmes run simultaneously when Green Flag pressed (demonstration to you)
- Interaction Evaluation Card completed for own and partner programme
- Exit Assessment
- "Explain to me why each character needs its OWN set of blocks." Target: learner explains that characters run simultaneously and independently. Write down: full explanation / partial / not yet.
- Differentiation
- Support: You adds Character 2 to the stage for the learner; learner focuses on building the 4-block sequence for Character 2 only (Character 1's sequence is pre-built).
- Extension: Add a third character (an audience member or narrator figure) with a minimal 2-block animation (e.g. waving) and write a 3-character story title. Then try to make one character APPEAR to respond to another by timing their movements (offset start positions and number of steps to appear to "meet" at the centre).

## Stay safe
Safeguarding Note: Story characters must be fictional only. You must not create characters that represent real classmates or teachers in negative scenarios.
