# Week 3 - Lesson 2

## Session length
**About half of this week's plan** (finish what you started in Lesson 1)

## Finish the week
- Explain a debugging process using three steps: Identify -> Locate -> Fix
- Find and correct two errors in a given Stack KIDI programme that does not behave as described
- Distinguish between a logic error (wrong order) and a wrong-block error (wrong instruction type)
- Document each bug found using a Bug Report Card: bug description, location, fix applied, result after fix

## Continue

### DELIVER - Debug the Three Programmes (32 min)
1. Programme 3 goal: "Character repeats: move forward 1, turn right - four times to make a square."
2. You read each goal and write in column 1 of the Bug Report Card: "What SHOULD happen."
3. PROGRAMME 1 - Wrong-Block Error (10 min): Open Buggy Project 1 on the tablet. Run it. What actually happens? (Character does NOT turn right - it turns left instead.) Place a red dot on the incorrect block. Fill in Bug Report Card: location = "Turn block, position 2". Fix = change Turn Left to Turn Right. Run again. Put green dot if fixed. Record: "Did the fix work?"
4. PROGRAMME 2 - Logic Error / Wrong Order (10 min): Open Buggy Project 2. Run it. What actually happens? (Character moves backward BEFORE spinning - goal says spin first.) Identify the logic error: blocks are in the wrong order. Fix = drag blocks to correct sequence. Re-run. Fill in Bug Report Card.
5. PROGRAMME 3 - Loop Count Error (12 min): Open Buggy Project 3. Run it. What happens? (Character makes only 2 turns of the square instead of 4 - the repeat number is 2, should be 4.) Identify: the number inside the Repeat End block is wrong. Fix = change from 2 to 4. Run and verify the full square is drawn. Fill in Bug Report Card.

### DISCOVER - Bug Report Debrief (9 min)
6. You who finish early: swap tablets with another pair and find the same bugs independently (without looking at your own Bug Report Cards).
7. One pair per programme presents: reads out their Bug Report Card for that programme.
8. Class checks: same bug? Same fix? Did anyone find a DIFFERENT bug in the same programme?
9. Facilitate discussion: "Which type of bug was hardest to find - wrong block or wrong order? Why?"
10. Key insight: "In Programme 3, changing the number 2 to 4 is a SMALL change that makes a BIG difference. This is why we fix ONE thing at a time."

### WRAP-UP (4 min)
11. Exit reflection: "A good debugger always ___." You complete the sentence individually.
12. Collect Bug Report Cards - kept in learner folders as portfolio evidence.
13. Write down: which you correctly identified all three bugs (checkmark on class register).
14. Preview: "Next lesson - we GIVE other people our code to debug. You will design a buggy programme for another pair to fix!"

## Check your understanding
- Formative (During)
- Bug Report Card completed for all 3 programmes (6 columns each)
- All 3 bugs correctly identified and described in plain English
- Fix verified by running the corrected programme (green dot placed)
- Distinction between logic error and wrong-block error explained verbally
- Exit Assessment
- Read the sentence starter: "A good debugger always ___." Target answer should include: reads the goal / tests one change at a time / does not guess randomly. Record whether you demonstrates systematic thinking.
- Differentiation
- Support: You pre-highlights the buggy block with a light yellow sticky note so the learner focuses on identifying and fixing (rather than locating). Extension: Learner deliberately introduces a new bug into your own Lesson 2 programme, writes a Bug Report Card for it, then swaps with another pair to find and fix each other's intentional bug.

## Stay safe
Safeguarding Note: Ensure you understand that making bugs is normal and not a failure. Use positive language: "Great detective work!" Avoid competitive framing that could make you feel embarrassed about not finding a bug quickly.
