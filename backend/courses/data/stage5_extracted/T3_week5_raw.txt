Core sensing and storage function (15 min): write void takeReading() { if(readCount >= 50) return; int raw = analogRead(A0); float ldr = raw / 1023.0; float temp = (analogRead(A1) * 5.0 / 1024.0 - 0.5) * 100.0; readings[readCount] = {readCount, ldr, temp, millis(), ""}; updateStats(ldr, temp); printReadingLine(readCount); readCount++; } Pairs write this in full.
Running statistics function (15 min): write void updateStats(float ldr, float temp) { int n = readCount + 1; ldrMean = ((ldrMean * readCount) + ldr) / n; if(ldr < ldrMin) ldrMin = ldr; if(ldr > ldrMax) ldrMax = ldr; tempMean = ((tempMean * readCount) + temp) / n; if(temp < tempMin) tempMin = temp; if(temp > tempMax) tempMax = temp; float ldrDev = ((ldr - ldrMean) / ldrMean) * 100.0; if(abs(ldrDev) > 20.0) { Serial.print("ALERT: LDR deviation "); Serial.print(ldrDev); Serial.println("%"); } } Hand-calculate a worked example first — see maths section — before typing.
Serial command handler (10 min): write void handleSerial() { if(Serial.available() > 0) { String cmd = Serial.readString(); cmd.trim(); if(cmd == "START") { logging = true; Serial.println("Logging started"); } else if(cmd == "STOP") { logging = false; Serial.println("Logging paused"); } else if(cmd == "REPORT") { printReport(); } else if(cmd == "RESET") { readCount = 0; ldrMean = 0.0; ldrMin = 1.0; ldrMax = 0.0; tempMean = 0.0; tempMin = 100.0; tempMax = -10.0; Serial.println("Reset complete"); } } } Add bool logging = false; as a global.
millis() integration (10 min): in loop(): unsigned long now = millis(); handleSerial(); if(logging && (now - lastReadTime >= 5000)) { lastReadTime = now; takeReading(); } Upload. Test: type "START" — readings begin. Type "STOP" — pause. Type "REPORT" — summary prints. Type "RESET" — clears.

English | Technical System Documentation is the highest-register technical writing task learners have encountered. Unlike a scientific report (which describes an experiment) or a design brief (which describes an intention), a system documentation describes an existing working system from the perspective of someone who must maintain or extend it. The Software Architecture section must list every function, its purpose in one precise sentence, what it receives, and what it produces — exactly like the architecture map from T3 Week 1, but now for a system the learner designed themselves. The Sample Output section requires learners to transcribe a real excerpt from the Serial Monitor and annotate it: explaining what each printed line means and which function produced it. The Limitations section must be analytically honest: "The programme cannot store more than 50 readings — after 50, new data overwrites old data or the logger must stop. This limits continuous monitoring to 50 × 5 = 250 seconds = 4.2 minutes."
Maths | Running statistics require understanding that statistics can be updated incrementally rather than recalculated from scratch each time. Running mean after n readings = ((previous mean × (n−1)) + newValue) ÷ n — Welford's method avoids summing all values for every update. Running min and max are simpler: compare the new value to the current min/max and update if necessary. Percentage deviation: deviation = ((newValue − mean) ÷ mean) × 100.0. A deviation of 20% triggers an alert. Learners calculate by hand: if the current mean ldrNorm is 0.620 and a new reading is 0.310, deviation = ((0.310 − 0.620) ÷ 0.620) × 100.0 = −50.0% — a significant drop that should trigger an alert. Time-series graph: plot ldrNorm and tempC on the same time axis (x = reading number, y = normalised value 0.0–1.0 for ldrNorm; secondary scale for tempC). This is the most complex graph in the programme — two dependent variables on the same x-axis.
