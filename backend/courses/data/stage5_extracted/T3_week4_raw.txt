Introduce precision and recall with a physical example (5 min): "Imagine a spam filter. It reviews 10 emails. 4 are truly spam. The filter marks 5 as spam. But 2 of the 5 it marked as spam are actually legitimate emails. Precision = 3 ÷ 5 = 60% (of everything it called spam, 60% was actually spam). Recall = 3 ÷ 4 = 75% (of all the actual spam, it caught 75%). Which matters more — precision or recall?" Discuss. Answer depends on context: for spam, low precision wastes time; for a medical test, low recall means missed diagnoses.
Distribute all printed materials. Explain the session structure: "First 60 minutes — collect training data and write rules. Final 50 minutes — test your classifier on cards you have never seen, build the confusion matrix, calculate the metrics, write the report."
Data collection sketch (10 min): write a sketch that reads both sensors every 2 seconds and prints: "LDR: [value] | Temp: [°C] | LightScore: [normalised]" to Serial Monitor. The normalised light score uses float lightScore = ldrValue / 1023.0;. Upload and verify both raw values and normalised score appear. Confirm float division is working correctly: if ldrValue = 0, lightScore should be 0.00; if ldrValue = 1023, lightScore should be 1.00.
Training data collection (25 min): collect 30 labelled readings. For each reading, manually label the true class in the training data table: COMFORTABLE (good light, comfortable temperature), WARM (too hot regardless of light), or DIM (too dark regardless of temperature). Vary conditions deliberately: cover the LDR, hold a warm hand near the TMP36, open a window or door. Aim for at least 8 readings of each class — note if any class is under-represented, as this introduces training data bias.
Feature engineering — add heat index (10 min): the raw TMP36 value has been converted to °C. Now engineer a second derived feature: bool isHot = (tempC > 27.0); — a Boolean that captures whether the temperature exceeds the comfort threshold. Extend the data table to include an isHot column and fill it for all 30 readings. Discuss: "This derived feature reduces a continuous float to a binary signal. Why might that make classification easier? What information is lost?"
Rule writing from data (15 min): inspect the training data table. For each class, find the range of lightScore and tempC values. The COMFORTABLE class should cluster around high lightScore AND low tempC. WARM clusters around high tempC regardless of lightScore. DIM clusters around low lightScore regardless of tempC. Write the threshold values on the rule writing worksheet with justification: "We chose lightScore < 0.35 for DIM because all 8 DIM readings had lightScore below 0.38, while all COMFORTABLE readings were above 0.40." Implement the rules as a nested if/else classifier in the Arduino sketch.
Held-out test set (15 min): facilitator distributes the 10 test set cards face-down. For each card, pairs read the LDR and TMP36 values, run the classifier sketch with those values (type them into a Serial.parseInt() input or hard-code each one temporarily), record the PREDICTED class from Serial Monitor output, then flip the card to reveal the TRUE class. Record both in the confusion matrix template. Do not look at the true class until after the prediction is made.
Confusion matrix completion (10 min): fill the 3×3 confusion matrix. Each row represents the true class; each column represents the predicted class. The diagonal cells (true COMFORTABLE predicted COMFORTABLE, etc.) are correct predictions. All off-diagonal cells are errors. Sum the diagonal: total correct predictions. Calculate accuracy = total correct ÷ 10.
Precision and recall calculation (10 min): for each class, calculate precision and recall using the confusion matrix. Show all working. Identify: which class has the lowest recall? What does this mean in practice — which type of environment is the classifier worst at detecting? Is the training data class distribution the cause?
AI Evaluation Report writing (15 min): write the 150-word report on the evaluation template. Must include: (1) what the classifier does and the dataset size, (2) the training methodology (how thresholds were chosen), (3) accuracy, precision, and recall with actual numbers, (4) one specific identified source of bias or error with the training data reference, (5) one specific improvement with a predicted effect on the metric it would improve.

English | The AI Evaluation Report is a piece of professional technical writing that mirrors the abstract and conclusions section of a research paper. It must synthesise four types of information: a description of the system, a summary of the methodology, a statement of results with numbers, and an evidence-based critique. "This classifier achieved an accuracy of 70% on the 10-item test set. The primary source of error was misclassification of the DIM class — 3 of the 4 DIM readings were classified as COMFORTABLE. This occurred because the training data contained only 6 DIM readings, making the rule boundary imprecise. Adding 10 more DIM readings to the training set, collected under genuinely dark conditions, would likely improve recall for the DIM class from 25% to over 70%." This writing standard — precise, data-grounded, specific about error sources, specific about improvement — is the highest English writing standard in the programme.
Maths | Precision and recall are the core evaluation metrics of any classification system. For a 3-class classifier evaluated on 10 test items: accuracy = total correct ÷ 10. Precision for COMFORTABLE = (number correctly classified as COMFORTABLE) ÷ (total classified as COMFORTABLE — including incorrect ones). Recall for COMFORTABLE = (number correctly classified as COMFORTABLE) ÷ (total that are actually COMFORTABLE in the test set). A confusion matrix makes this visual: the diagonal cells are the correct predictions; the off-diagonal cells are the errors. Learners read the matrix and identify which class was most often confused with which other class. Feature normalisation: dividing ldrValue by 1023.0 maps the sensor range (0–1023) to a unit interval (0.0–1.0) — this is linear normalisation, a standard pre-processing step in every machine learning pipeline. Learners calculate: if ldrValue = 750, normalised score = 750 ÷ 1023.0 = 0.733. This is a float division calculation requiring correct understanding of integer vs float arithmetic.

The confidence score is the distance from the nearest decision boundary — expressed as a proportion of the full threshold range. Print both the class label and the confidence to Serial Monitor. Calculate: for a reading of lightScore = 0.42 with a boundary at 0.35, the confidence for the DIM vs COMFORTABLE decision = (0.42 − 0.35) ÷ (1.0 − 0.35) = 0.108 = 10.8%. Low confidence means the reading is close to a boundary — a real AI system would flag this for human review.
